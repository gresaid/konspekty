**Что проверяет задание 27**

В этих задачах дано множество точек. Его нужно разбить на кластеры по рисунку или по описанию, а потом внутри каждого кластера найти специальную точку. Дальше остаётся выполнить требование условия: усреднить координаты центров, выбрать нужный кластер, найти ближайшую точку заданного типа, посчитать расстояние между центрами или вместо центра взять антицентр.

Схема почти всегда одна и та же: сначала восстановить геометрию кластеров, потом отдельно обработать каждый из них.

**Порядок решения**

Удобно держать в голове такой порядок:

1. Прочитать точки из файла.
2. По рисунку или условию восстановить границы кластеров.
3. Разложить точки по кластерам через проверки на `x` и `y`.
4. Для каждого кластера найти центр или антицентр.
5. Выполнить дополнительное действие из условия.
6. Привести ответ к нужному формату: `int(...)`, масштабирование, модуль, округление вниз.

**Как выделять кластеры**

Границы кластеров редко даны готовыми формулами. Обычно их приходится считывать с рисунка и переводить в проверки.

| Тип границы | Как выглядит проверка |
| --- | --- |
| Вертикальная | `x < a`, `x > a` |
| Горизонтальная | `y < b`, `y > b` |
| Наклонная прямая | сравнение `y` со значением прямой |
| Составная область | несколько условий одновременно |

После этого точки раскладывают по спискам:

```python
clusters = [[] for _ in range(k)]
```

Дальше каждая точка должна попасть ровно в один рабочий кластер. Если в данных есть аномалии, шумовые точки или промежуточная область, их не включают в расчёты, если условие прямо не просит этого делать.

**Что такое центр кластера**

Самая частая ошибка здесь — принять центр кластера за среднее арифметическое координат. В задании 27 это обычно неверно.

Центр — это точка из самого кластера, для которой сумма расстояний до всех остальных точек минимальна.

Если кандидат на центр равен `p`, то оценивается величина

`sum(r(p, q) for q in cl)`

где `cl` — текущий кластер.

Именно точка с минимальной суммой и считается центром.

Базовая функция расстояния:

```python
def r(p1, p2):
    return ((p1[0] - p2[0]) ** 2 + (p1[1] - p2[1]) ** 2) ** 0.5
```

Базовый шаблон поиска центра:

```python
def center(cl):
    return min(cl, key=lambda p: sum(r(p, q) for q in cl))
```

`min(...)` сразу выбирает лучшую точку, поэтому промежуточный список сумм здесь не нужен.

**Когда нужен антицентр**

Антицентр ищется так же, только теперь нужна точка с наибольшей суммой расстояний.

```python
def anti_center(cl):
    return max(cl, key=lambda p: sum(r(p, q) for q in cl))
```

По сути меняется только `min` на `max`.

**Когда центр бывает взвешенным**

Иногда у точки есть вес: например, высота дерева, масса или другая характеристика. Тогда минимизируют уже не простую сумму расстояний, а сумму вида `расстояние * вес`.

Если точка хранится как `[x, y, w]`, шаблон становится таким:

```python
def center(cl):
    return min(cl, key=lambda p: sum(r(p[:2], q[:2]) * q[2] for q in cl))
```

Здесь:

- `p` — кандидат на центр;
- `q[:2]` — координаты очередной точки;
- `q[2]` — её вес.

Если по условию нужен взвешенный антицентр, схема остаётся той же, только используется `max(...)`.

**Как может быть записана точка**

Состав записи зависит от конкретного прототипа.

| Вид точки | Что хранится |
| --- | --- |
| `[x, y]` | только координаты |
| `[x, y, w]` | координаты и вес |
| `[x, y, color, lum]` | координаты и дополнительные признаки |

Здесь важно не смешивать роли полей:

- расстояние считается только по координатам;
- фильтрация может использовать дополнительные признаки;
- взвешенная сумма использует вес.

Поэтому в коде часто встречается `p[:2]`: так берут только `x` и `y`.

**Что делают после нахождения центров**

После нахождения центров или антицентров задача обычно сводится к одному из стандартных действий.

| Что нужно получить | Типичный приём |
| --- | --- |
| Средние координаты центров | `px = sum(p[0] for p in centers) / k` |
| Нужный кластер | `min(clusters, key=len)`, `max(clusters, key=len)` |
| Ближайшую точку к центру | `min(points, key=lambda p: r(p[:2], c[:2]))` |
| Самую удалённую пару | двойной перебор всех пар |

Если нужно сравнить расстояния до начала координат, корень можно не извлекать:

```python
min(centers, key=lambda p: p[0] ** 2 + p[1] ** 2)
```

Так можно делать, потому что квадрат расстояния и само расстояние задают один и тот же порядок точек.

**Чтение данных**

Часто координаты в файле записаны через запятую, поэтому строку сначала приводят к привычному виду:

```python
x, y = [float(t) for t in line.replace(',', '.').split()]
```

Если в строке есть не только координаты, но и описание объекта, поля читают отдельно.

Например:

```python
x, y, stats = line.split()
```

Дальше строковое поле разбирают уже по правилам конкретного прототипа. Это частная часть решения, поэтому её обычно объясняют в разборе соответствующей задачи.

**Почему прямой перебор подходит**

После разбиения на кластеры число точек внутри одного кластера обычно остаётся умеренным, поэтому можно без хитрых оптимизаций перебрать всех кандидатов на центр.

Для кластера из `n` точек такой поиск работает за `O(n^2)`:

- выбираем точку-кандидат;
- считаем сумму расстояний до всех точек кластера;
- сравниваем результат с текущим лучшим.

Для типовых данных задания 27 этого хватает.

**Типичные ошибки**

- путать центр кластера со средним арифметическим координат;
- искать центр сразу по всему файлу, не разбивая точки на кластеры;
- неточно снять границы кластеров с рисунка;
- включить аномалии в рабочие кластеры;
- считать расстояние по всем полям точки, а не только по координатам;
- перепутать `min` и `max` в задачах на центр и антицентр;
- заменить сумму расстояний суммой квадратов расстояний, хотя условие этого не требует;
- забыть проверить формат ответа: `int(...)`, умножение на `10000` или `100000`, модуль.

**Короткая шпаргалка**

- Сначала восстановить границы кластеров.
- Потом разложить точки по спискам.
- Центр: `min(..., key=сумма расстояний)`.
- Антицентр: `max(..., key=сумма расстояний)`.
- Взвешенный вариант: `расстояние * вес`.
- Дополнительные условия применять после поиска центров, если в условии не сказано иное.
- Перед ответом отдельно проверить масштабирование и формат вывода.

## Прямоугольные кластеры фиксированного размера

### Прототип A

**Текст задания**  
Учёный решил провести кластеризацию некоторого множества звёзд по их расположению на карте звёздного неба. Кластер звёзд — это набор звёзд, лежащий внутри прямоугольника высотой `H` и шириной `W`. Каждая звезда принадлежит ровно одному кластеру.

Истинный центр кластера, или центроид, — это одна из звёзд, сумма расстояний от которой до всех остальных звёзд этого кластера минимальна.

Под расстоянием понимается расстояние Евклида между точками `A(x1, y1)` и `B(x2, y2)`:

`d(A, B) = ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5`

В файле `A` хранятся данные о звёздах трёх кластеров, где `H = 5`, `W = 5` для каждого кластера. В каждой строке записаны координаты одной звезды: сначала `x`, затем `y`. Известно, что количество звёзд не превышает `1000`.

В файле `B` хранятся данные о звёздах четырёх кластеров, где `H = 5`, `W = 5` для каждого кластера. Количество звёзд не превышает `10000`. Формат строк такой же, как в файле `A`.

Для каждого файла нужно:
- определить координаты центра каждого кластера;
- вычислить `Px` — среднее арифметическое абсцисс центров;
- вычислить `Py` — среднее арифметическое ординат центров.

В ответе нужно записать четыре числа:
- в первой строке — `int(Px * 10000)` и `int(Py * 10000)` для файла `A`;
- во второй строке — аналогичные величины для файла `B`.

Возможные данные одного из файлов иллюстрированы графиком. График приведён только для пояснения и не совпадает с реальными данными задания.

Файлы к заданию: [27_A.txt](https://kompege.ru/files/TSFAOtZ7z.txt), [27_A.xlsx](https://kompege.ru/files/gVutLDzRP.xlsx), [27_B.txt](https://kompege.ru/files/YGqilfVrX.txt), [27_B.xlsx](https://kompege.ru/files/vxkchu-Xq.xlsx)

**Иллюстрация реальных данных**

**Идея решения**  
В обоих файлах сначала нужно разбить точки на кластеры по их расположению. После этого для каждого кластера ищется центроид: точка с минимальной суммой расстояний до остальных точек этого же кластера.

В этом варианте после анализа рисунка получаются простые границы:
- для файла `A`: сначала отделяется левый кластер условием `x < 6`, затем верхний средний кластер условием `y > 23`, оставшиеся точки образуют третий кластер;
- для файла `B`: точки удобно сначала разделить на две горизонтальные полосы по условию `y < 10`, а внутри каждой полосы — на левую и правую части по условию `x < 15`.

**Код решения**
```python
def read_points(filename):
    points = []
    with open(filename) as f:
        next(f)
        for line in f:
            x, y = line.split()
            x = float(x.replace(',', '.'))
            y = float(y.replace(',', '.'))
            points.append((x, y))
    return points


def r(p1, p2):
    return ((p1[0] - p2[0]) ** 2 + (p1[1] - p2[1]) ** 2) ** 0.5


def center(cl):
    return min(cl, key=lambda p: sum(r(p, p1) for p1 in cl))


def solve_a(points):
    clusters = [[] for _ in range(3)]

    for x, y in points:
        if x < 6:
            clusters[0].append((x, y))
        elif y > 23:
            clusters[1].append((x, y))
        else:
            clusters[2].append((x, y))

    centers = [center(cl) for cl in clusters]
    px = sum(x for x, y in centers) / 3
    py = sum(y for x, y in centers) / 3
    return int(px * 10000), int(py * 10000)


def solve_b(points):
    clusters = [[] for _ in range(4)]

    for x, y in points:
        if y < 10:
            if x < 15:
                clusters[0].append((x, y))
            else:
                clusters[1].append((x, y))
        else:
            if x < 15:
                clusters[2].append((x, y))
            else:
                clusters[3].append((x, y))

    centers = [center(cl) for cl in clusters]
    px = sum(x for x, y in centers) / 4
    py = sum(y for x, y in centers) / 4
    return int(px * 10000), int(py * 10000)


points_a = read_points('27_A.txt')
points_b = read_points('27_B.txt')

print(*solve_a(points_a))
print(*solve_b(points_b))
```

**Разбор решения**  
а) Файл `A`.  
Точки образуют три хорошо разделённые группы. Сначала удобно выделить левый кластер по условию `x < 6`. Среди оставшихся точек верхний кластер отделяется условием `y > 23`, а всё остальное попадает в третий кластер. Для каждого из трёх списков вызывается функция `center(cl)`, после чего усредняются координаты найденных центров.

б) Файл `B`.  
Здесь кластеры образуют сетку `2 x 2`. Поэтому разбиение делается в два шага: сначала по горизонтали `y < 10`, затем внутри каждой полосы по вертикали `x < 15`. После этого для каждого из четырёх кластеров снова находится центроид, а затем считаются средние значения `Px` и `Py`.

## Клиновидные кластера

### Прототип A

**Текст задания**  
Фрагмент звёздного неба спроецирован на плоскость с декартовой системой координат. Учёный решил провести кластеризацию полученных точек, являющихся изображениями звёзд, то есть разбить их множество на `N` непересекающихся непустых подмножеств, таких что точки каждого подмножества лежат внутри сектора круга радиусом `R` и центральным углом `H` градусов, причём эти сектора между собой не пересекаются. Гарантируется, что такое разбиение существует и единственно.

Центром кластера будем называть точку этого кластера, сумма расстояний от которой до всех остальных точек кластера минимальна. Для каждого кластера гарантируется единственность его центра.

Даны два входных файла: [файл A](https://kpolyakov.spb.ru/cms/files/ege-cluster/63/27-63a.txt) и [файл Б](https://kpolyakov.spb.ru/cms/files/ege-cluster/63/27-63b.txt).

В файле `A` хранятся данные о звёздах трёх кластеров с параметрами `R = 5` и `H = 30`. В каждой строке записаны координаты одной звезды: сначала `x`, затем `y`. Количество звёзд не превышает `1000`.

В файле `Б` такой же структуры хранятся данные о звёздах пяти кластеров с параметрами `R = 10` и `H = 45`. Количество звёзд не превышает `10000`.

Для каждого файла нужно определить координаты центра каждого кластера, затем вычислить:
- `Px` — среднее арифметическое абсцисс центров;
- `Py` — среднее арифметическое ординат центров.

В ответе нужно записать четыре числа:
- в первой строке — `int(Px * 100000)` и `int(Py * 100000)` для файла `A`;
- во второй строке — аналогичные величины для файла `Б`.

**Иллюстрация реальных данных**  
![Сектора файлов 27-63A и 27-63B через граничные прямые](/Y:/Trash/YandexDisk/YandexDisk/Продукт/КОНСПЕКТЫ/27_аналитика/files/sector_clusters_63_lines.png)

**Идея решения**  
В этой задаче кластеры удобно выделять не по углам напрямую, а через граничные прямые, которые образуют стороны секторов.

После анализа рисунка видно:
- для файла `A` все три сектора имеют вершину в точке `(5, 5)`;
- для файла `Б` все пять секторов имеют вершину в точке `(10, 10)`.

Дальше для каждой границы выписывается уравнение прямой по двум точкам.  
Например, для файла `Б` одна из границ проходит через точки `(10, 10)` и `(17, 18)`. Тогда

`(y - 10) / (18 - 10) = (x - 10) / (17 - 10)`

откуда

`7 * (y - 10) = 8 * (x - 10)`

`y = 8 * (x - 10) / 7 + 10`

После этого сектор задаётся просто как система неравенств: точка должна лежать выше одной граничной прямой и ниже другой. В коде это удобно записывать прямо в `if`.

**Код решения**
```python
def read_points(filename):
    points = []
    with open(filename) as f:
        for line in f:
            x, y = line.replace(',', '.').split()
            points.append((float(x), float(y)))
    return points


def r(p1, p2):
    return ((p1[0] - p2[0]) ** 2 + (p1[1] - p2[1]) ** 2) ** 0.5


def center(cl):
    return min(cl, key=lambda p: sum(r(p, p1) for p1 in cl))


def solve_a(points):
    clusters = [[] for _ in range(3)]

    for x, y in points:
        if y >= (x - 5) / (3 ** 0.5) + 5 and y <= (3 ** 0.5) * (x - 5) + 5:
            clusters[0].append((x, y))
        elif y >= -0.3639702343 * (x - 5) + 5 and y <= -1.1917535926 * (x - 5) + 5:
            clusters[1].append((x, y))
        else:
            clusters[2].append((x, y))

    centers = [center(cl) for cl in clusters]
    px = sum(x for x, y in centers) / 3
    py = sum(y for x, y in centers) / 3
    return int(px * 100000), int(py * 100000)


def solve_b(points):
    clusters = [[] for _ in range(5)]

    for x, y in points:
        if y >= 0.0874886635 * (x - 10) + 10 and y <= 0.8390996312 * (x - 10) + 10:
            clusters[0].append((x, y))
        elif y >= 1.1917535926 * (x - 10) + 10 and y <= 11.4300523028 * (x - 10) + 10:
            clusters[1].append((x, y))
        elif y >= 0.8390996312 * (x - 10) + 10 and y <= 0.0874886635 * (x - 10) + 10:
            clusters[2].append((x, y))
        elif y >= 11.4300523028 * (x - 10) + 10 and y <= 1.1917535926 * (x - 10) + 10:
            clusters[3].append((x, y))
        else:
            clusters[4].append((x, y))

    centers = [center(cl) for cl in clusters]
    px = sum(x for x, y in centers) / 5
    py = sum(y for x, y in centers) / 5
    return int(px * 100000), int(py * 100000)


points_a = read_points('27-63a.txt')
points_b = read_points('27-63b.txt')

print(*solve_a(points_a))
print(*solve_b(points_b))
```

**Разбор решения**  
а) Файл `A`.  
Все точки лежат в трёх узких секторах с вершиной в `(5, 5)`. Поэтому для границ выписываются уравнения прямых, проходящих через эту точку. Дальше в `if` прямо проверяется, лежит ли точка между двумя нужными прямыми. Первый сектор задаётся двумя возрастающими прямыми, второй — двумя убывающими, третий получается как оставшаяся область.

б) Файл `Б`.  
Здесь вершина секторов находится в точке `(10, 10)`, а кластеров уже пять. Для каждой границы заранее выписано уравнение прямой по двум точкам, а затем сектор задаётся как система неравенств. **Идея решения**  
Геометрически задача здесь простая: кластеры хорошо разделены. Но кроме поиска центров нужно ещё правильно разобрать строковое обозначение звезды и отфильтровать точки по типу.

В этой задаче понадобятся три набора признаков:
- красные гиганты: `M...III`;
- оранжевые гиганты: `K...III`;
- жёлтые карлики: `G...V`.

Поэтому сначала каждая строка разбирается на координаты и признаки звезды, потом точки раскладываются по кластерам, и только после этого используются фильтры по цвету и светимости.

def read_points(filename):
    points = []
    with open(filename) as f:
        for line in f:
            x, y, stats = line.split()
            x = float(x.replace(',', '.'))
            y = float(y.replace(',', '.'))

            if stats == 'VII':
                color = ''
                subclass = ''
                size = 'VII'
            else:
                color = stats[0]
                i = 1
                while i < len(stats) and stats[i].isdigit():
                    i += 1
                subclass = stats[1:i]
                size = stats[i:]

            points.append((x, y, color, subclass, size))
    return points


def r(p1, p2):
    return ((p1[0] - p2[0]) ** 2 + (p1[1] - p2[1]) ** 2) ** 0.5


def center(cl):
    return min(cl, key=lambda p: sum(r(p, p1) for p1 in cl))


def solve_a(points):
    clusters = [[], []]

    for p in points:
        if p[1] < 12:
            clusters[0].append(p)
        else:
            clusters[1].append(p)

    centers = [center(cl) for cl in clusters]
    small = min(clusters, key=len)
    c = center(small)

    red_giants = [p for p in small if p[2] == 'M' and p[4] == 'III']
    ans = min(red_giants, key=lambda p: r(p, c))

    return int(abs(ans[0]) * 10000), int(abs(ans[1]) * 10000)


def solve_b(points):
    clusters = [[], [], []]

    for p in points:
        if p[1] < 30:
            clusters[0].append(p)
        elif p[0] < 16.7:
            clusters[1].append(p)
        else:
            clusters[2].append(p)

    centers = [center(cl) for cl in clusters]

    orange_giants = [
        [p for p in cl if p[2] == 'K' and p[4] == 'III']
        for cl in clusters
    ]

    min_i = min(range(3), key=lambda i: len(orange_giants[i]))
    max_i = max(range(3), key=lambda i: len(orange_giants[i]))
    b1 = r(centers[min_i], centers[max_i])

    yellow_dwarfs = [
        [p for p in cl if p[2] == 'G' and p[4] == 'V']
        for cl in clusters
    ]

    b2 = 0
    for g in yellow_dwarfs:
        for i in range(len(g)):
            for j in range(i + 1, len(g)):
                b2 = max(b2, r(g[i], g[j]))

    return int(b1 * 10000), int(b2 * 10000)


points_a = read_points('27_A.txt')
points_b = read_points('27_B.txt')

print(*solve_b(points_b))

а) Файл `A`.

б) Файл `B`.  
Нижний кластер отделяется по `y < 30`, а два верхних — по `x < 16.7`. После поиска центров отдельно считаются количества оранжевых гигантов `K...III` в каждом кластере. По ним вычисляется `B1`. Затем в каждом кластере отбираются жёлтые карлики `G...V`, и перебором всех пар находится максимальное расстояние `B2`.
