# ТЕОРИЯ

## Жадный алгоритм

Жадный алгоритм выбирает лучший доступный вариант на текущем шаге и больше не пересматривает этот выбор.

Такой подход работает не всегда. Он подходит только для задач, где локально выгодный ход не мешает получить лучший итоговый ответ.

Типичные формулировки:

- выбрать как можно больше объектов при ограниченном ресурсе;
- построить самую длинную цепочку по простому правилу;
- выбрать максимум непересекающихся отрезков;
- сначала получить максимум по одному параметру, затем улучшить второй ответ внутри этого максимума.

## Почему в жадных задачах нужна сортировка

Жадный выбор почти всегда начинается с сортировки. Она задаёт порядок, в котором удобно принимать одинаковое решение на каждом шаге.

Например:

- для архивации файлов размеры сортируются по возрастанию;
- для коробок размеры сортируются по убыванию;
- для расписания мероприятия сортируются по времени окончания.

После сортировки решение обычно превращается в один проход по списку.

## Главный и дополнительный критерии

Во многих задачах 26 есть два ответа. Первый ответ главный, второй уточняет лучший вариант.

Например:

- сначала сохранить максимальное число файлов, потом найти максимальный размер файла среди таких наборов;
- сначала построить максимальную цепочку коробок, потом сделать самую маленькую коробку как можно больше;
- сначала выбрать максимум мероприятий, потом увеличить перерыв между двумя последними.

Нельзя улучшать второй ответ ценой ухудшения первого. Сначала фиксируется максимум по главному критерию, затем внутри этого максимума ищется лучший второй параметр.

## Основные жадные приёмы

**Брать самые маленькие объекты.**

Если нужно уместить как можно больше объектов в ограниченный объём, выгодно сначала брать минимальные размеры. Маленький объект расходует меньше ресурса и оставляет больше места для следующих.

**Идти от больших значений к меньшим.**

Если нужно построить цепочку и сделать последний элемент как можно больше, часто выгодно начинать с максимального элемента и каждый раз брать самый большой подходящий следующий.

**Брать отрезок с самым ранним окончанием.**

В задачах на расписание стандартный выбор - мероприятие, которое заканчивается раньше всех среди допустимых. Чем раньше освободился зал, тем больше вариантов остаётся для продолжения.

## Частые ошибки

- Улучшать второй ответ до того, как найден максимум по первому.
- Выбирать крупные файлы при задаче на максимальное количество файлов.
- Строить цепочку коробок снизу вверх, хотя нужно максимизировать размер самой маленькой коробки.
- В задачах на мероприятия сортировать по времени начала вместо времени окончания.
- Проверять пересечение мероприятий строгим сравнением, хотя мероприятие можно начинать ровно в момент окончания предыдущего.

## Прототип 1. Архивация файлов пользователей

**Текст задания**

Системный администратор раз в неделю создаёт архив пользовательских файлов. Однако объём диска, куда он помещает архив, может быть меньше, чем суммарный объём архивируемых файлов. Известно, какой объём занимает файл каждого пользователя. По заданной информации об объёме файлов пользователей и свободном объёме на архивном диске определите максимальное число пользователей, чьи файлы можно сохранить в архиве, а также максимальный размер имеющегося файла, который может быть сохранён в архиве, при условии, что сохранены файлы максимально возможного числа пользователей. 

Входные данные. 

В первой строке входного файла находятся два числа: S – размер свободного места на диске (натуральное число, не превышающее 10 000) и N – количество пользователей (натуральное число, не превышающее 1000). В следующих N строках находятся значения объёмов файлов каждого пользователя (все числа натуральные, не превышающие 100), каждое в отдельной строке. 

Запишите в ответе два числа: сначала наибольшее число пользователей, чьи файлы могут быть помещены в архив, затем максимальный размер имеющегося файла, который может быть сохранён в архиве, при условии, что сохранены файлы максимально возможного числа пользователей. 

**Идея решения**

Главный критерий - количество файлов. Чтобы сохранить как можно больше файлов, нужно начинать с самых маленьких размеров.

После сортировки по возрастанию файлы добавляются в архив, пока хватает места. Так находится максимальное количество.

Второй ответ ищется после этого. Из уже выбранного набора временно убирается самый большой выбранный файл. Освободившееся место равно остатку памяти плюс размер этого файла. Затем среди всех файлов ищется самый большой размер, который помещается в это место.

Пример:

```python
S = 17
files = [1, 2, 4, 5, 8, 9]
```

Сначала выбираются файлы:

```python
1 + 2 + 4 + 5 = 12
```

Остаётся `5`, количество файлов равно `4`. Если убрать последний выбранный файл размера `5`, доступное место для замены станет:

```python
5 + 5 = 10
```

Самый большой файл не больше `10` - это `9`. Значит, набор можно заменить на:

```python
1, 2, 4, 9
```

Количество файлов не изменилось, а максимальный размер файла стал больше.

**Код решения**

```python
f = open('26.txt')
s, n = map(int, f.readline().split())
data = sorted(int(x) for x in f)

selected = []

for x in data:
    if x <= s:
        selected.append(x)
        s -= x

count_files = len(selected)
free_space = s + selected[-1]

for x in reversed(data):
    if x <= free_space:
        print(count_files, x)
        break
```

**Подробный разбор**

`data` - отсортированный список размеров файлов. Переменная `s` хранит текущее свободное место на диске.

Список `selected` содержит файлы, которые удалось добавить в архив на первом этапе. Цикл идёт по размерам от меньших к большим:

```python
for x in data:
    if x <= s:
        selected.append(x)
        s -= x
```

Если файл помещается, он добавляется в архив, а свободное место уменьшается на его размер.

После первого прохода:

- `count_files` - максимальное количество файлов;
- `selected[-1]` - самый большой файл среди выбранных;
- `free_space` - место, доступное для замены последнего выбранного файла.

Второй цикл просматривает все размеры с конца, от больших к маленьким:

```python
for x in reversed(data):
    if x <= free_space:
        print(count_files, x)
        break
```

Первый подходящий `x` и будет максимальным размером файла для второго ответа.

**Ответ**

```python
568 50
```

## Прототип 2. Коробки для упаковки по принципу матрёшки

**Текст задания**

 В магазине для упаковки подарков есть N кубических коробок. Самой интересной считается упаковка подарка по принципу матрёшки – подарок упаковывается в одну из коробок, та в свою очередь в другую коробку и т.д. Одну коробку можно поместить в другую, если длина её стороны хотя бы на 3 единицы меньше длины стороны другой коробки. Определите наибольшее количество коробок, которое можно использовать для упаковки одного подарка, и максимально возможную длину стороны самой маленькой коробки, где будет находиться подарок. Размер подарка позволяет поместить его в самую маленькую коробку.

Входные данные

В первой строке входного файла находится число N – количество коробок в магазине (натуральное число, не превышающее 10 000). В следующих N строках находятся значения длин сторон коробок (все числа натуральные, не превышающие 10 000), каждое – в отдельной строке.

Запишите в ответе два целых числа: сначала наибольшее количество коробок, которое можно использовать для упаковки одного подарка, затем максимально возможную длину стороны самой маленькой коробки в таком наборе.

Типовой пример организации данных во входном файле

5
43
40
32
40
30

Пример входного файла приведён для пяти коробок и случая, когда минимальная допустимая разница между длинами сторон коробок, подходящих для упаковки «матрёшкой», составляет 3 единицы.

При таких исходных данных условию задачи удовлетворяют наборы коробок с длинами сторон 30, 40 и 43 или 32, 40 и 43 соответственно, т.е. количество коробок равно 3, а длина стороны самой маленькой коробки равна 32

**Идея решения**

Здесь тоже два критерия: сначала длина цепочки, затем размер самой маленькой коробки.

Чтобы второй ответ был как можно больше, цепочку строят от больших коробок к меньшим. После выбора очередной коробки берётся самая большая коробка из оставшихся, которая меньше предыдущей хотя бы на `3`.

Пример:

```python
43, 40, 32, 40, 30
```

После сортировки по убыванию:

```python
43, 40, 40, 32, 30
```

Цепочка строится так:

```python
43 -> 40 -> 32
```

После `40` коробка `30` тоже подходит, но `32` больше. При той же длине цепочки она даёт лучший второй ответ.

**Код решения**

```python
f = open('26.txt')
n = int(f.readline())
data = sorted((int(x) for x in f), reverse=True)

boxes = [data[0]]

for x in data[1:]:
    if boxes[-1] - x >= 3:
        boxes.append(x)

print(len(boxes), boxes[-1])
```

**Подробный разбор**

`data` хранит размеры коробок по убыванию. Первая коробка в списке - самая большая, поэтому цепочка начинается с неё:

```python
boxes = [data[0]]
```

Дальше перебираются остальные размеры:

```python
for x in data[1:]:
    if boxes[-1] - x >= 3:
        boxes.append(x)
```

Срез `data[1:]` означает, что перебор начинается со второго элемента списка.

Первую коробку уже взяли в цепочку строкой:

```python
boxes = [data[0]]
```

Если снова проходить по всему `data`, самая большая коробка проверялась бы повторно. Она не может быть вложена сама в себя, поэтому в основном цикле нужны только оставшиеся коробки.

`boxes[-1]` - последняя выбранная коробка. Условие проверяет, можно ли вложить текущую коробку в неё.

Если разность меньше `3`, коробка пропускается. Если разность не меньше `3`, коробка добавляется в цепочку.

Например:

```python
20, 19, 17, 14, 12, 11, 8
```

Цепочка получится такой:

```python
20, 17, 14, 11, 8
```

Ответ на первый вопрос - `len(boxes)`. Ответ на второй вопрос - `boxes[-1]`, последняя и самая маленькая коробка в построенной цепочке.

**Ответ**

```python
2767 51
```

## Прототип 3. Заявки на мероприятия в конференц-зале

**Текст задания**

 Входной файл содержит сведения о заявках на проведение мероприятий в конференц-зале. В каждой заявке указаны время начала и время окончания мероприятия (в минутах от начала суток). Если время начала одного мероприятия меньше времени окончания другого, то провести можно только одно из них. Если время окончания одного мероприятия совпадает со временем начала другого, то провести можно оба. Определите, какое максимальное количество мероприятий можно провести в конференц-зале и каков при этом максимально возможный перерыв между двумя последними мероприятиями.
Входные данные
В первой строке входного файла находится натуральное число N (N ≤ 1000) – количество заявок на проведение мероприятий. Следующие N строк содержат пары чисел, обозначающих время начала и время окончания мероприятий. Каждое из чисел натуральное, не превосходящее 1440. 
Запишите в ответе два числа: максимальное количество мероприятий и самый длинный перерыв между двумя последними мероприятиями (в минутах).
Типовой пример организации данных во входном файле
5
10 150
100 120
131 170
150 180
120 130
При таких исходных данных можно провести максимум три мероприятия, например, мероприятия по заявкам 2, 3 и 5. Максимальный перерыв между двумя последними мероприятиями составит 20 мин., если состоятся мероприятия по заявкам 2, 4 и 5.
Типовой пример имеет иллюстративный характер. Для выполнения задания используйте данные из прилагаемых файлов.

**Идея решения**

Для максимального количества мероприятий используется классический жадный алгоритм: сортировка по времени окончания и выбор ближайшего мероприятия, которое начинается не раньше конца предыдущего.

Для второго ответа важно не потерять найденный максимум. После жадного прохода берём время окончания предпоследнего мероприятия в оптимальной цепочке. Перед ним уже можно провести максимальное количество мероприятий минус одно. Последним можно поставить любое мероприятие, которое начинается не раньше этого времени. Чтобы перерыв был максимальным, выбираем среди таких мероприятий самое позднее по началу.

Пример:

```python
(10, 150), (100, 120), (120, 130), (131, 170), (150, 180)
```

Максимум по количеству равен `3`. Если предпоследнее мероприятие заканчивается в `130`, то последним лучше взять мероприятие с началом `150`, а не `131`:

```python
150 - 130 = 20
```

**Код решения**

```python
f = open('26.txt')
n = int(f.readline())
data = []

for line in f:
    start, end = map(int, line.split())
    data.append([start, end])

data.sort(key=lambda x: x[1])

last = -1
events = []

for event in data:
    if event[0] >= last:
        last = event[1]
        events.append(event)

count_events = len(events)
prev_end = events[-2][1]

max_start = 0

for start, end in data:
    if start >= prev_end and start > max_start:
        max_start = start

print(count_events, max_start - prev_end)
```

**Подробный разбор**

`data` хранит пары `[начало, окончание]`. Сортировка по окончанию задаёт правильный порядок для жадного выбора:

```python
data.sort(key=lambda x: x[1])
```

Переменная `last` хранит время окончания последнего выбранного мероприятия. В список `events` попадают мероприятия оптимального расписания:

```python
for event in data:
    if event[0] >= last:
        last = event[1]
        events.append(event)
```

Условие `event[0] >= last` разрешает начинать мероприятие ровно в момент окончания предыдущего.

После первого прохода `count_events` - максимальное количество мероприятий.

Для второго ответа берётся окончание предпоследнего мероприятия:

```python
prev_end = events[-2][1]
```

Дальше среди всех заявок ищется самое позднее начало, которое не раньше `prev_end`:

```python
for start, end in data:
    if start >= prev_end and start > max_start:
        max_start = start
```

Разность `max_start - prev_end` даёт максимальный перерыв между двумя последними мероприятиями.

**Ответ**

```python
32 15
```
