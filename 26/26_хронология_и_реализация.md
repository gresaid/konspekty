## Хронологическая реализация

В задачах на хронологию события моделируются в том порядке, в котором они происходят во времени. Обычно даны заявки, интервалы, моменты прихода, освобождения ресурса или окончания работы. По этим данным нужно понять, какие события реально произойдут при заданных правилах.

Главная идея таких задач: программа должна повторять правила из условия, а не выбирать удобный набор объектов. Если пассажир приходит в конкретную минуту, решение должно проверить состояние системы именно к этой минуте.

Типичные объекты в таких задачах:

- ячейки камеры хранения;
- залы, окна обслуживания, парковочные места;
- заявки с началом и окончанием;
- ресурсы, которые могут быть заняты или свободны.

## Почему заявки нужно сортировать по времени

Если во входном файле перечислены заявки, это не всегда означает, что они уже стоят в правильном порядке. Для моделирования нужно обрабатывать их по времени события:

```python
zayavki.sort()
```

Если каждая заявка записана парой `[nachalo, konec]`, обычная сортировка сначала упорядочит заявки по `nachalo`, а при равенстве - по `konec`.

Без сортировки программа может принять позднюю заявку раньше ранней и получить неверное состояние ячеек, залов или других ресурсов.

## Хранение состояния ресурсов

Удобный способ хранить занятость ресурсов - список, где номер элемента соответствует номеру ресурса.

Например, если есть `kolvo_yacheek` ячеек камеры хранения:

```python
yacheyki = [0] * kolvo_yacheek
```

Значение `yacheyki[nomer_yacheyki]` показывает время, до которого занята ячейка с номером `nomer_yacheyki + 1`. Нумерация в Python начинается с нуля, а в условии ячейки обычно нумеруются с единицы, поэтому при выводе номера используется `nomer_yacheyki + 1`.

Для каждой заявки перебираются ячейки по порядку:

```python
for nomer_yacheyki in range(kolvo_yacheek):
    if yacheyki[nomer_yacheyki] < nachalo:
        yacheyki[nomer_yacheyki] = konec
        break
```

Так автоматически выбирается свободная ячейка с минимальным номером.

## Сортировка событий разных типов

Иногда в задаче нужно упорядочить не сами объекты, а все связанные с ними числа. Например, у каждой детали есть два времени: шлифовка и окрашивание. Тогда из одной детали получается два события:

```python
sobytiya.append([shlifovka, 'shlifovka', nomer])
sobytiya.append([okraska, 'okraska', nomer])
```

После сортировки событий по времени программа рассматривает самое маленькое ещё не использованное число. Если деталь уже получила место, второе число этой же детали пропускается.

Для этого удобно хранить список отметок:

```python
razmesheno = [False] * (kolvo_detalei + 1)
```

Когда деталь размещена, ставим:

```python
razmesheno[nomer] = True
```

Так программа не размещает одну и ту же деталь дважды.

## Заполнение последовательности с двух концов

В некоторых задачах итоговый порядок строится не только слева направо. Если объект нужно поставить либо в начало, либо в конец свободной части, удобно хранить два указателя:

```python
levo = 0
pravo = kolvo_detalei - 1
poryadok = [0] * kolvo_detalei
```

Если объект ставится в первое свободное место от начала:

```python
poryadok[levo] = nomer
levo += 1
```

Если объект ставится в первое свободное место от конца:

```python
poryadok[pravo] = nomer
pravo -= 1
```

Так список `poryadok` постепенно заполняется с двух сторон.

## Моделирование очередей

Если ресурс обслуживает клиентов по одному, очередь удобно хранить как список времён окончания обслуживания. Каждое число в списке относится к клиенту, который уже обслуживается или ждёт своей очереди.

Перед обработкой нового клиента нужно удалить из очереди всех, кто уже закончил обслуживание:

```python
ochered = [konec for konec in ochered if konec > prihod]
```

Если обслуживание заканчивается ровно в момент прихода нового клиента, такой клиент уже не занимает очередь. Поэтому остаются только времена строго больше `prihod`.

Время начала обслуживания нового клиента:

```python
if len(ochered) == 0:
    nachalo = prihod
else:
    nachalo = ochered[-1]
```

Если очередь пуста, обслуживание начинается в момент прихода. Если очередь не пуста, новый клиент начнёт обслуживание после последнего клиента в этой очереди.

В очередь добавляется время окончания обслуживания:

```python
ochered.append(nachalo + dlitelnost)
```

Длина списка после удаления завершивших обслуживание показывает, сколько человек сейчас связано с этим окном: и ожидающие, и тот, кого обслуживают.

## Двумерная занятость

Если объект задаётся двумя номерами, например вагоном и местом, удобно хранить занятость в двумерном списке:

```python
zanyato = [[False] * (kolvo_mest + 1) for _ in range(kolvo_vagonov + 1)]
```

Индексы `0` не используются, зато номера из условия можно применять напрямую:

```python
zanyato[vagon][mesto]
```

Если нужно найти первое свободное место по правилу "минимальный вагон, внутри него минимальное место", используется вложенный перебор:

```python
for nomer_vagona in range(1, kolvo_vagonov + 1):
    for nomer_mesta in range(1, kolvo_mest + 1):
        if not zanyato[nomer_vagona][nomer_mesta]:
            zanyato[nomer_vagona][nomer_mesta] = True
            break
```

В таких задачах важно не просто найти любое свободное место, а соблюдать порядок поиска, заданный условием.

## Строгие и нестрогие границы времени

Самая частая ошибка в хронологических задачах - неправильно обработать момент освобождения ресурса.

Если в условии сказано, что новый объект можно разместить в только что освобождённый ресурс начиная со следующей минуты, проверка должна быть строгой:

```python
yacheyki[nomer_yacheyki] < nachalo
```

Это означает: ячейка освободилась раньше момента сдачи багажа.

Если бы в условии было сказано, что ресурс можно занять в ту же минуту, проверка была бы другой:

```python
yacheyki[nomer_yacheyki] <= nachalo
```

Короткий пример:

```python
yacheyki[nomer_yacheyki] = 60
nachalo = 60
```

При условии "со следующей минуты" ячейка ещё не подходит, потому что освобождение занимает эту минуту. Следующий багаж можно положить только при `nachalo = 61`.

## Общий шаблон решения

Для задач, где нужно распределять заявки по ресурсам, часто подходит такой шаблон:

```python
fayl = open('26.txt')
kolvo_yacheek = int(fayl.readline())
kolvo_zayavok = int(fayl.readline())
zayavki = [list(map(int, stroka.split())) for stroka in fayl]
zayavki.sort()

yacheyki = [0] * kolvo_yacheek
kolichestvo = 0
poslednyaya_yacheyka = 0

for nachalo, konec in zayavki:
    for nomer_yacheyki in range(kolvo_yacheek):
        if yacheyki[nomer_yacheyki] < nachalo:
            yacheyki[nomer_yacheyki] = konec
            kolichestvo += 1
            poslednyaya_yacheyka = nomer_yacheyki + 1
            break

print(kolichestvo, poslednyaya_yacheyka)
```

В этом шаблоне:

- `zayavki` хранит заявки;
- `yacheyki` хранит время освобождения каждой ячейки;
- внешний цикл перебирает заявки по времени;
- внутренний цикл ищет первую подходящую ячейку;
- `kolichestvo` считает принятые заявки;
- `poslednyaya_yacheyka` хранит номер ячейки, занятой последней принятой заявкой.

## Типичные ошибки

- Обрабатывать заявки в порядке файла, если файл не отсортирован по времени.
- Использовать `<=` вместо `<`, когда ресурс можно занять только со следующей минуты.
- Забывать, что минимальный номер ячейки получается перебором `for nomer_yacheyki in range(kolvo_yacheek)`.
- Выводить индекс Python `nomer_yacheyki` вместо номера ячейки `nomer_yacheyki + 1`.
- Обновлять номер последней ячейки даже для заявки, которую не удалось принять.
- Искать максимальный номер занятой ячейки вместо номера ячейки, которую заняли последней по времени.
- Размещать объект дважды, если в отсортированном списке встретились оба его числа.
- Путать номер последней размещённой детали с её позицией в итоговом порядке.
- В задачах с очередями забывать удалить клиентов, обслуживание которых завершилось к моменту прихода нового клиента.
- Считать только ожидающих в очереди, хотя по условию в ограничение может входить и обслуживаемый клиент.
- При работе с двумерной занятостью использовать индексы Python вместо номеров из условия.
- Искать свободное место не в том порядке, который указан в условии.

## Прототип 1. Камера хранения

**Текст задания**

(№ 8512) Входной файл содержит заявки пассажиров, желающих сдать свой багаж в камеру хранения. В заявке указаны время сдачи багажа и время освобождения ячейки (в минутах от начала суток). Багаж одного пассажира размещается в одной свободной ячейке с минимальным номером. Ячейки пронумерованы начиная с единицы. Размещение багажа в ячейке или её освобождение происходит в течение 1 мин. Багаж можно поместить в только что освобождённую ячейку начиная со следующей минуты. Если в момент сдачи багажа свободных ячеек нет, то пассажир уходит. Определите, сколько пассажиров сможет сдать свой багаж в течение 24 ч и какой номер будет иметь ячейка, которую займут последней. Если таких ячеек несколько, укажите минимальный номер ячейки.

Входные данные

В первой строке входного файла находится натуральное число `K`, не превышающее 1000, - количество ячеек в камере хранения. Во второй строке - натуральное число `N` (`N <= 1000`), обозначающее количество пассажиров. Каждая из следующих `N` строк содержит два натуральных числа, каждое из которых не превышает 1440: указанное в заявке время размещения багажа в ячейке и время освобождения ячейки.

Запишите в ответе два числа: количество пассажиров, которые смогут воспользоваться камерой хранения, и номер последней занятой ячейки.

**Идея решения**

Нужно смоделировать работу камеры хранения в течение суток.

Каждая ячейка хранит время, когда она освободится. Для новой заявки проверяем ячейки от первой к последней. Первая ячейка, у которой время освобождения меньше времени сдачи багажа, подходит.

Проверка строгая:

```python
yacheyki[nomer_yacheyki] < nachalo
```

Если ячейка освобождается в минуту `60`, новый багаж можно положить только с минуты `61`, потому что освобождение занимает 1 минуту.

Заявки сортируются по времени сдачи багажа. После этого один проход по заявкам полностью повторяет хронологию событий.

**Код решения**

```python
fayl = open('26_8512.txt')
kolvo_yacheek = int(fayl.readline())
kolvo_passazhirov = int(fayl.readline())
zayavki = [list(map(int, stroka.split())) for stroka in fayl]
zayavki.sort()

yacheyki = [0] * kolvo_yacheek
kolichestvo = 0
poslednyaya_yacheyka = 0

for nachalo, konec in zayavki:
    for nomer_yacheyki in range(kolvo_yacheek):
        if yacheyki[nomer_yacheyki] < nachalo:
            yacheyki[nomer_yacheyki] = konec
            kolichestvo += 1
            poslednyaya_yacheyka = nomer_yacheyki + 1
            break

print(kolichestvo, poslednyaya_yacheyka)
```

**Разбор решения**

`zayavki` содержит пары `[nachalo, konec]`: время сдачи багажа и время освобождения ячейки. Сортировка нужна, чтобы рассматривать пассажиров в порядке прихода.

`yacheyki` - список занятости ячеек. Если `yacheyki[0] = 610`, значит ячейка 1 занята до минуты 610 включительно с учётом правила про следующую минуту.

Для каждой заявки внутренний цикл перебирает ячейки с меньших номеров к большим. Поэтому первая найденная подходящая ячейка автоматически имеет минимальный номер.

Если условие `yacheyki[nomer_yacheyki] < nachalo` выполнено, пассажир может сдать багаж:

- в ячейку записывается новое время освобождения `konec`;
- счётчик принятых пассажиров увеличивается;
- `poslednyaya_yacheyka` получает номер этой ячейки;
- `break` завершает поиск, потому что одному пассажиру нужна только одна ячейка.

Если свободной ячейки нет, внутренний цикл завершается без изменений: пассажир уходит, счётчик и номер последней ячейки не обновляются.

Ограничения небольшие: `K <= 1000`, `N <= 1000`. Перебор всех ячеек для каждой заявки даёт не более `10^6` проверок, поэтому такая реализация подходит по времени.

**Проверка на примере**

Для фрагмента:

```text
2
5
30 60
40 1000
59 60
61 1000
1010 1440
```

первый пассажир занимает ячейку 1, второй - ячейку 2. Третий приходит в минуту 59, но ячейка 1 освобождается только в минуту 60, поэтому она ещё не подходит. Четвёртый приходит в минуту 61 и может занять ячейку 1. Пятый занимает ячейку 1, потому что к этому моменту обе ячейки свободны, а выбирать нужно минимальный номер.

**Ответ**

```text
389 133
```

## Прототип 2. Шлифовка и окрашивание деталей

**Текст задания**

(№ 9793) На производстве штучных изделий `N` деталей должны быть отшлифованы и окрашены. Для каждой детали известно время её шлифовки и время окрашивания. Детали пронумерованы начиная с единицы. Параллельная обработка деталей не предусмотрена.

На ленте транспортёра имеется `N` мест для каждой из `N` деталей.

На ленте транспортёра детали располагают по следующему алгоритму:

- все `2N` чисел, обозначающих время окрашивания и шлифовки для `N` деталей, упорядочивают по возрастанию;
- если минимальное число в этом упорядоченном списке - это время шлифовки конкретной детали, то деталь размещают на ленте транспортёра на первое свободное место от её начала;
- если минимальное число - это время окрашивания, то деталь размещают на первое свободное место от конца ленты транспортёра;
- если число обозначает время окрашивания или шлифовки уже рассмотренной детали, то его не принимают во внимание.

Этот алгоритм применяется последовательно для размещения всех `N` деталей.

Определите номер последней детали, для которой будет определено её место на ленте транспортёра, и количество деталей, которые будут отшлифованы до неё.

Входные данные

В первой строке входного файла находится натуральное число `N` (`N < 1000`) - количество деталей. Следующие `N` строк содержат пары чисел, обозначающих соответственно время шлифовки и время окрашивания конкретной детали. Все числа натуральные и различные.

Запишите в ответе два натуральных числа: сначала номер последней детали, для которой будет определено её место на ленте транспортёра, затем количество деталей, которые будут отшлифованы до неё.

**Идея решения**

Здесь не нужно моделировать саму шлифовку и окрашивание по минутам. Нужно точно выполнить алгоритм построения порядка деталей на ленте.

Для каждой детали создаём два события:

- время шлифовки;
- время окрашивания.

После сортировки всех событий по возрастанию первое ещё не использованное событие определяет, куда поставить деталь:

- если это шлифовка, ставим деталь в левую свободную часть ленты;
- если это окрашивание, ставим деталь в правую свободную часть ленты.

Деталь, которая получила место, помечается как рассмотренная. Когда второе число этой же детали встретится позже, оно пропускается.

Последняя рассмотренная деталь - это деталь, для которой место было определено последней. Чтобы узнать, сколько деталей будут отшлифованы до неё, нужно найти её позицию в итоговом порядке. Поскольку индексы Python начинаются с нуля, индекс детали в списке равен количеству деталей перед ней.

**Код решения**

```python
fayl = open('26_9793.txt')
kolvo_detalei = int(fayl.readline())

sobytiya = []

for nomer in range(1, kolvo_detalei + 1):
    shlifovka, okraska = map(int, fayl.readline().split())
    sobytiya.append([shlifovka, 'shlifovka', nomer])
    sobytiya.append([okraska, 'okraska', nomer])

sobytiya.sort()

razmesheno = [False] * (kolvo_detalei + 1)
poryadok = [0] * kolvo_detalei
levo = 0
pravo = kolvo_detalei - 1
poslednyaya_detal = 0

for vremya, tip, nomer in sobytiya:
    if razmesheno[nomer]:
        continue

    razmesheno[nomer] = True
    poslednyaya_detal = nomer

    if tip == 'shlifovka':
        poryadok[levo] = nomer
        levo += 1
    else:
        poryadok[pravo] = nomer
        pravo -= 1

do_nee = poryadok.index(poslednyaya_detal)

print(poslednyaya_detal, do_nee)
```

**Разбор решения**

`sobytiya` хранит все числа из условия вместе с их смыслом и номером детали. Например, для детали 7 с временами `120` и `300` в список попадут два события:

```python
[120, 'shlifovka', 7]
[300, 'okraska', 7]
```

После сортировки программа рассматривает события от меньшего времени к большему. Все числа в файле различны, поэтому дополнительная обработка равенств не нужна.

`razmesheno[nomer]` показывает, получила ли деталь место на ленте. Если деталь уже была размещена по меньшему из двух своих чисел, второе событие пропускается командой `continue`.

`levo` указывает на первое свободное место от начала ленты, `pravo` - на первое свободное место от конца. Поэтому:

- событие `shlifovka` заполняет `poryadok[levo]`;
- событие `okraska` заполняет `poryadok[pravo]`.

Переменная `poslednyaya_detal` обновляется только в момент реального размещения детали. После завершения цикла в ней остаётся номер детали, получившей место последней.

Количество деталей, которые будут отшлифованы до неё, равно количеству деталей перед ней в итоговом порядке. Это индекс детали в списке `poryadok`:

```python
do_nee = poryadok.index(poslednyaya_detal)
```

**Проверка на примере**

Для примера из условия итоговый порядок деталей на ленте:

```text
4 1 2 3 5
```

Последней место получает деталь 3. Перед ней в порядке ленты стоят детали 4, 1 и 2, поэтому количество деталей до неё равно 3.

**Ответ**

```text
895 488
```

## Прототип 3. Два окна в банке

**Текст задания**

(№ 13101) В отделении банка работают два окна для обслуживания клиентов. Некоторые услуги могут быть оказаны только при обращении в определённое окно, некоторые - при обращении в любое окно. Клиент входит в отделение и встаёт в очередь к тому окну, которое оказывает необходимую ему услугу. Если услуга может быть оказана в любом окне, клиент выбирает то, в очереди к которому в данный момент меньше людей. Если очереди в оба окна одинаковые, клиент выбирает окно с меньшим номером. При этом если в очереди к выбранному окну уже стоит 14 или более человек, включая человека, которого обслуживают в данный момент, пришедший клиент сразу уходит.

Если момент завершения обслуживания одного или нескольких клиентов совпадает с моментом прихода нового клиента, то можно считать, что новый клиент пришёл после того, как обслуживание ранее пришедшего клиента завершилось и очередь сократилась.

Входные данные

Первая строка входного файла содержит целое число `N` (`N <= 1000`) - общее количество клиентов, пришедших в отделение за один рабочий день. Каждая из следующих `N` строк описывает одного клиента и содержит 3 целых числа: время прихода клиента в отделение, время, необходимое для обслуживания данного клиента, и номер окна, в которое ему необходимо обратиться. Значение `0` означает, что клиент может обратиться в любое окно. Гарантируется, что никакие два клиента не приходят одновременно.

Определите, сколько клиентов будет обслужено в течение дня в окне номер 2 и сколько клиентов покинет отделение из-за слишком больших очередей.

В ответе запишите два целых числа: сначала количество клиентов, обслуженных в окне номер 2, затем количество необслуженных клиентов.

**Идея решения**

Для каждого окна будем хранить очередь как список времён окончания обслуживания клиентов. В списке находятся и клиент, которого обслуживают сейчас, и те, кто ждёт.

Перед приходом очередного клиента нужно убрать из обеих очередей всех, кто уже закончил обслуживание. По условию, если обслуживание завершилось ровно в момент прихода, очередь уже сократилась, поэтому оставляем только времена окончания, которые строго больше времени прихода.

После очистки выбираем окно:

- если в заявке указано `1`, клиент идёт только в окно 1;
- если указано `2`, клиент идёт только в окно 2;
- если указано `0`, выбирается более короткая очередь, а при равенстве - окно 1.

Если в выбранной очереди уже 14 или больше человек, клиент уходит. Иначе добавляем в очередь время окончания его обслуживания.

**Код решения**

```python
fayl = open('26_13101.txt')
kolvo_klientov = int(fayl.readline())
klienty = [list(map(int, stroka.split())) for stroka in fayl]
klienty.sort()

ochered1 = []
ochered2 = []
obsluzheno_vo_2 = 0
ushli = 0

for prihod, dlitelnost, okno in klienty:
    ochered1 = [konec for konec in ochered1 if konec > prihod]
    ochered2 = [konec for konec in ochered2 if konec > prihod]

    if okno == 1:
        ochered = ochered1
    elif okno == 2:
        ochered = ochered2
    else:
        if len(ochered1) <= len(ochered2):
            ochered = ochered1
        else:
            ochered = ochered2

    if len(ochered) >= 14:
        ushli += 1
        continue

    if len(ochered) == 0:
        nachalo = prihod
    else:
        nachalo = ochered[-1]

    ochered.append(nachalo + dlitelnost)

    if ochered is ochered2:
        obsluzheno_vo_2 += 1

print(obsluzheno_vo_2, ushli)
```

**Разбор решения**

`klienty` хранит тройки чисел: время прихода, длительность обслуживания и номер окна. Сортировка нужна, потому что в файле клиенты могут быть записаны не по времени прихода.

`ochered1` и `ochered2` - очереди к первому и второму окну. В них хранятся не номера клиентов, а времена окончания обслуживания. Этого достаточно, чтобы понимать длину очереди и вычислять, когда начнёт обслуживаться следующий клиент.

Строки:

```python
ochered1 = [konec for konec in ochered1 if konec > prihod]
ochered2 = [konec for konec in ochered2 if konec > prihod]
```

убирают всех клиентов, которые к моменту `prihod` уже освободили очередь. Строгое сравнение `>` соответствует условию: если обслуживание закончилось ровно в момент прихода, новый клиент видит уже сокращённую очередь.

Для услуги с номером окна `0` выбирается очередь меньшей длины. Условие `len(ochered1) <= len(ochered2)` сразу учитывает правило выбора окна 1 при равенстве.

Проверка:

```python
if len(ochered) >= 14:
```

выполняется до добавления нового клиента. Если в выбранной очереди уже 14 человек или больше, клиент не обслуживается, а счётчик `ushli` увеличивается.

Если клиент принят, время начала обслуживания равно:

- `prihod`, если очередь пуста;
- `ochered[-1]`, если перед ним уже есть клиенты.

После добавления времени окончания `nachalo + dlitelnost` очередь остаётся упорядоченной по времени завершения обслуживания.

Счётчик `obsluzheno_vo_2` увеличивается только для клиентов, которые действительно попали в окно 2. Ушедшие клиенты в него не входят.

**Ответ**

```text
126 469
```

## Прототип 4. Бронирование мест в поезде

**Текст задания**

(№ 14622) Скоростной поезд, направляющийся из Москвы в Санкт-Петербург, ожидает пассажиров. Состав поезда включает в себя `K` сцепленных пассажирских вагонов, каждый из которых содержит `M` пассажирских мест. Вагоны и места в них нумеруются от 1 до `K` и от 1 до `M` соответственно.

Известен перечень из `N` заявок на бронь билетов за вчерашний день. В каждой заявке указано время подачи заявки, желаемый номер вагона и номер места в нём. Оператор обрабатывает заявки последовательно, начиная с ранее поданных. Среди заявок, поданных в одинаковое время, прежде обрабатываются заявки с наименьшими номерами вагонов, а если номера вагонов совпали - с наименьшими номерами мест.

Если указанное в заявке место в нужном вагоне ещё свободно, оператор утверждает билет на это место. Иначе он утверждает билет на наименьшее по номеру свободное место, расположенное в вагоне, который находится как можно ближе к кабине машиниста. Вагон с кабиной машиниста имеет нулевой номер и не является пассажирским. Если свободных мест нет, билет не утверждается.

Определите количество пассажиров, которые получили билет в несоответствии со своей заявкой, а также сумму номеров вагона и места в последнем утверждённом билете.

Входные данные

В первой строке входного файла находится натуральное число `K` - количество пассажирских вагонов (`K <= 100`). Во второй строке содержится натуральное число `M` - количество мест в каждом вагоне (`M <= 100`). В третьей строке - натуральное число `N` (`N <= 10000`), обозначающее количество заявок. Каждая из следующих `N` строк содержит три натуральных числа: время подачи заявки, желаемый номер вагона и желаемый номер места.

Запишите в ответе два числа: сначала количество пассажиров, которые получили билет в несоответствии со своей заявкой, а затем сумму номеров вагона и места в последнем утверждённом билете.

**Идея решения**

Нужно обработать заявки в том же порядке, что и оператор. Для этого сортируем тройки:

```python
[vremya, vagon, mesto]
```

Обычная сортировка списка троек подходит сразу: сначала сравнивается время, затем номер вагона, затем номер места.

Занятость мест храним в двумерном списке `zanyato`. Если желаемое место свободно, занимаем его. Если оно уже занято, ищем первое свободное место по правилу из условия:

- вагон с минимальным номером;
- внутри него место с минимальным номером.

Если пассажир получает не то место, которое просил, увеличиваем счётчик `ne_sovpalo`. После каждого утверждённого билета запоминаем вагон и место, чтобы в конце вывести сумму для последнего утверждённого билета.

**Код решения**

```python
fayl = open('26_14622.txt')
kolvo_vagonov = int(fayl.readline())
kolvo_mest = int(fayl.readline())
kolvo_zayavok = int(fayl.readline())
zayavki = [list(map(int, stroka.split())) for stroka in fayl]
zayavki.sort()

zanyato = [[False] * (kolvo_mest + 1) for _ in range(kolvo_vagonov + 1)]
ne_sovpalo = 0
posledniy_vagon = 0
poslednee_mesto = 0

for vremya, vagon, mesto in zayavki:
    if not zanyato[vagon][mesto]:
        zanyato[vagon][mesto] = True
        posledniy_vagon = vagon
        poslednee_mesto = mesto
    else:
        nashli = False

        for nomer_vagona in range(1, kolvo_vagonov + 1):
            for nomer_mesta in range(1, kolvo_mest + 1):
                if not zanyato[nomer_vagona][nomer_mesta]:
                    zanyato[nomer_vagona][nomer_mesta] = True
                    ne_sovpalo += 1
                    posledniy_vagon = nomer_vagona
                    poslednee_mesto = nomer_mesta
                    nashli = True
                    break

            if nashli:
                break

print(ne_sovpalo, posledniy_vagon + poslednee_mesto)
```

**Разбор решения**

`zayavki` хранит заявки в виде троек: время подачи, желаемый вагон, желаемое место. После сортировки заявки идут ровно в порядке обработки оператором. Дополнительный `key` не нужен, потому что Python сравнивает списки слева направо.

`zanyato[vagon][mesto]` показывает, занято ли конкретное место. Нулевые строка и столбец не используются, чтобы не переводить номера из условия в индексы Python.

Если желаемое место свободно, билет утверждается без изменения заявки. В этом случае счётчик `ne_sovpalo` не увеличивается.

Если место занято, запускается вложенный перебор:

```python
for nomer_vagona in range(1, kolvo_vagonov + 1):
    for nomer_mesta in range(1, kolvo_mest + 1):
```

Так сначала проверяются места в вагоне 1, затем в вагоне 2 и далее. Внутри каждого вагона места тоже идут по возрастанию. Это соответствует правилу: выбрать свободное место в вагоне как можно ближе к кабине машиниста, а внутри вагона - место с минимальным номером.

Переменная `nashli` нужна, чтобы остановить оба цикла после первого найденного свободного места. Если свободных мест нет, заявка остаётся без утверждённого билета: счётчик `ne_sovpalo` не увеличивается, а данные последнего утверждённого билета не меняются.

`posledniy_vagon` и `poslednee_mesto` обновляются только после утверждения билета. В конце выводится не сам вагон и место, а их сумма:

```python
posledniy_vagon + poslednee_mesto
```

**Проверка на примере**

В примере из условия заявки после сортировки по времени обрабатываются не в порядке записи в файле. Билеты без изменений получают заявки на свободные места, а последняя утверждённая заявка получает место `1` в вагоне `1` вместо запрошенного места. Поэтому для примера ответ равен:

```text
1 2
```

**Ответ**

```text
2391 114
```
