# ТЕОРИЯ

## Что такое жадный алгоритм
Жадный алгоритм — это способ решения задачи, при котором на каждом шаге выбирают лучший вариант из доступных прямо сейчас и не пересматривают уже сделанный выбор.

Идея такая:
- в текущий момент выбирается локально лучший ход;
- предполагается, что последовательность таких ходов приведёт к правильному итоговому ответу.

Жадный алгоритм работает не во всех задачах. Его можно применять только там, где локально выгодный выбор действительно сохраняет путь к оптимальному ответу.

## Как распознать жадную задачу
Обычно у жадных задач есть один из таких признаков:
- нужно набрать максимум объектов при ограниченном ресурсе;
- нужно минимизировать расход на каждом шаге;
- выгодный выбор легко описывается словами: брать самое маленькое, самое большое, самое раннее, самое дешёвое;
- после правильного выбора на текущем шаге задача остаётся такой же по смыслу для оставшейся части данных.

## Простой пример жадного выбора
Пусть нужно уместить как можно больше файлов в диск объёмом `10`, а размеры файлов такие:

```python
8, 1, 2, 3
```

Если начать с файла `8`, останется `2`, и тогда удастся взять только `8` и `2`. Получится 2 файла.

Если сначала брать самые маленькие файлы, получится:

```python
1 + 2 + 3 = 6
```

В архив поместятся уже 3 файла.

Значит, для цели "сохранить как можно больше" выгодно не занимать место крупными файлами слишком рано, а набирать минимальные размеры.

## Почему в этой группе задач часто нужна сортировка
Если выгодно брать элементы в порядке увеличения или уменьшения, данные обычно сначала сортируют.

Сортировка превращает общую идею в простой алгоритм:
- упорядочить данные;
- идти по ним слева направо или справа налево;
- на каждом шаге принимать одно и то же решение.

## Что важно помнить
В жадных задачах всегда нужно очень чётко понимать, что именно оптимизируется.

Если в задаче сказано:
- сначала получить максимум по количеству;
- потом среди таких вариантов улучшить ещё один параметр,

то второй шаг нельзя решать отдельно от первого. Сначала фиксируется главный оптимум, и только потом внутри него улучшается дополнительный ответ.

## Когда направление жадного прохода влияет на второй ответ
Иногда один и тот же максимум по количеству можно получить двумя симметричными способами:
- идти от меньших значений к большим;
- идти от больших значений к меньшим.

Для первого критерия оба подхода могут быть равноправны. Но если в задаче есть второй вопрос, направление прохода уже становится важным.

Если нужно сделать как можно больше самый маленький элемент в найденной цепочке, выгодно строить цепочку от больших значений к меньшим. Тогда на каждом шаге выбирается максимально возможный следующий элемент, и последний выбранный элемент тоже получается максимально возможным.

## Когда выгодно брать событие с самым ранним окончанием
В задачах про расписания, занятия, мероприятия и заявки часто требуется выбрать максимальное число непересекающихся отрезков времени.

В таких задачах стандартный жадный выбор такой:
- сначала упорядочить все мероприятия по времени окончания;
- затем каждый раз брать то мероприятие, которое заканчивается раньше всех среди допустимых.

Почему это выгодно: чем раньше заканчивается текущее мероприятие, тем больше свободного времени остаётся для следующих. Значит, такой выбор не уменьшает количество вариантов продолжения.

## Как искать второй ответ в задаче на расписание
Если после максимума по количеству нужно оптимизировать ещё и промежуток между двумя последними мероприятиями, то обычного одного жадного прохода уже недостаточно.

В таких задачах часто удобно разделять решение на две части:
- сначала кодом найти максимальное количество мероприятий;
- затем использовать найденное расписание как опору и отдельно разобрать последние мероприятия.

Если решение делается полуручно, обычно достаточно:
- построить одно оптимальное расписание;
- зафиксировать время окончания предпоследнего мероприятия;
- среди всех мероприятий, которые начинаются не раньше этого времени, выбрать самое позднее по началу.

Тогда разность между началом этого последнего мероприятия и окончанием предпоследнего и даст нужный перерыв.

## Прототип 1. Архивация файлов пользователей

**Текст задания**

Системный администратор раз в неделю создаёт архив пользовательских файлов. Однако объём диска, куда он помещает архив, может быть меньше, чем суммарный объём архивируемых файлов. Известно, какой объём занимает файл каждого пользователя. По заданной информации об объёме файлов пользователей и свободном объёме на архивном диске определите максимальное число пользователей, чьи файлы можно сохранить в архиве, а также максимальный размер имеющегося файла, который может быть сохранён в архиве, при условии, что сохранены файлы максимально возможного числа пользователей.

В первой строке входного файла находятся два числа: `S` — размер свободного места на диске и `N` — количество пользователей. В следующих `N` строках находятся значения объёмов файлов каждого пользователя.

Нужно вывести два числа: сначала максимальное количество пользователей, затем максимальный размер файла, который можно сохранить при этом количестве.

**Идея решения**

В задаче два вопроса.

Первый вопрос: какое максимальное число файлов можно записать.

Второй вопрос: какой наибольший файл можно оставить в архиве, если число записанных файлов уже максимально.

Первый вопрос главный. Пока на него нет ответа, ко второму переходить нельзя.

Чтобы сохранить как можно больше файлов, нужно брать самые маленькие размеры. Тогда каждый следующий файл расходует минимум памяти и оставляет максимум места для остальных.

Когда максимальное количество уже найдено, можно улучшать второй ответ: попытаться заменить самый большой из выбранных файлов на более крупный, но так, чтобы число файлов не уменьшилось.

**Первая оптимизация**

Сначала нужно отсортировать все размеры файлов по возрастанию и последовательно добавлять их в архив, пока хватает места.

Почему это правильно, видно на простом примере.

Пусть объём диска равен `10`, а размеры файлов такие:

```python
8, 4, 3, 2, 1
```

После сортировки получаем:

```python
1, 2, 3, 4, 8
```

Теперь сравним два подхода.

Если взять крупный файл `8`, то останется `2`, и больше одного маленького файла уже не добавить:

```python
8 + 2 = 10
```

Получилось только 2 файла.

Если идти от меньших размеров:

```python
1 + 2 + 3 + 4 = 10
```

Получится уже 4 файла.

Именно поэтому для первого вопроса жадный выбор здесь такой: брать минимальные файлы по возрастанию.

**Вторая оптимизация**

После первого этапа уже известно максимальное количество файлов. Теперь нужно получить как можно больший размер файла, не теряя это количество.

Разберём пример.

Пусть объём диска равен `17`, а размеры файлов после сортировки такие:

```python
1, 2, 4, 5, 8, 9
```

Идём по порядку:

```python
1 + 2 + 4 + 5 = 12
```

Остаётся `5` единиц.

Следующий файл `8` уже не помещается. Значит, максимальное количество файлов равно `4`.

На первом этапе выбраны файлы:

```python
[1, 2, 4, 5]
```

Теперь второй вопрос. Нужно сохранить те же `4` файла, но сделать максимальный размер одного из них как можно больше.

Если оставить первые три файла:

```python
1 + 2 + 4 = 7
```

то на четвёртый файл можно потратить:

```python
17 - 7 = 10
```

Это то же самое, что взять остаток свободного места после первого этапа и прибавить размер последнего выбранного файла:

```python
5 + 5 = 10
```

Теперь среди всех имеющихся файлов нужно найти самый большой файл размера не больше `10`.

В нашем списке это `9`.

Значит, вместо набора

```python
[1, 2, 4, 5]
```

можно взять

```python
[1, 2, 4, 9]
```

Количество файлов останется равным `4`, но максимальный размер файла увеличится с `5` до `9`.

В этом и состоит второй шаг решения.

**Код решения**

```python
f = open('26.txt')
s, n = map(int, f.readline().split())
data = sorted(int(x) for x in f)

a = []

for x in data:
    if x <= s:
        a.append(x)
        s -= x

count_files = len(a)
free_space = s + a[-1]

for x in reversed(data):
    if x <= free_space:
        print(count_files, x)
        break
```

**Подробный разбор**

Сначала считываются данные:

```python
s, n = map(int, f.readline().split())
data = sorted(int(x) for x in f)
```

`s` — это текущее свободное место на диске.

`n` — число пользователей.

`data` — отсортированный список размеров всех файлов.

Сортировка нужна, чтобы идти от самых маленьких файлов к самым большим.

Дальше создаётся список выбранных файлов:

```python
a = []
```

В него будут записываться те размеры, которые удалось поместить в архив.

Первый цикл отвечает на первый вопрос:

```python
for x in data:
    if x <= s:
        a.append(x)
        s -= x
```

Что здесь происходит:
- `x` — текущий размер файла;
- проверяется, помещается ли файл в оставшееся место;
- если помещается, файл добавляется в список `a`;
- свободное место `s` уменьшается на размер этого файла.

Разберём короткий пример.

Пусть после сортировки получили:

```python
2, 3, 3, 6, 9
```

а объём диска равен `11`.

Тогда цикл работает так:

```python
берём 2, остаётся 9
берём 3, остаётся 6
берём 3, остаётся 3
6 уже не помещается
9 уже не помещается
```

В итоге:

```python
a = [2, 3, 3]
```

Это и есть максимальное количество файлов.

Количество найденных файлов:

```python
count_files = len(a)
```

Теперь нужно ответить на второй вопрос.

Последний элемент `a[-1]` — самый большой файл среди уже выбранных. Если временно убрать его из набора, то освободится дополнительное место.

Это место считается так:

```python
free_space = s + a[-1]
```

Здесь:
- `s` — остаток памяти после записи всех выбранных файлов;
- `a[-1]` — размер последнего выбранного файла.

Разберём смысл на примере.

Пусть после первого этапа:

```python
a = [2, 3, 3]
```

и осталось:

```python
s = 3
```

Если убрать последний файл размера `3`, то доступное место станет:

```python
3 + 3 = 6
```

Значит, теперь можно искать самый большой файл, который не превышает `6`.

Для этого список просматривается с конца:

```python
for x in reversed(data):
    if x <= free_space:
        print(count_files, x)
        break
```

`reversed(data)` даёт файлы от самого большого к самому маленькому.

Как только найден первый файл, который помещается, это и есть лучший ответ на второй вопрос.

`break` нужен потому, что дальше пойдут только меньшие размеры, а значит, лучшего ответа уже не будет.

Разберём пример до конца.

Пусть:

```python
data = [2, 3, 3, 6, 9]
free_space = 6
```

Проверка идёт так:

```python
9 не помещается
6 помещается
```

Значит, вместо выбранного набора

```python
[2, 3, 3]
```

можно взять набор

```python
[2, 3, 6]
```

Количество файлов остаётся тем же, но максимальный размер файла становится больше.

Для файла из задания программа даёт ответ:

```python
568 50
```

Это значит:
- можно сохранить файлы `568` пользователей;
- при этом максимальный размер файла, который можно оставить в архиве, равен `50`.

**Ответ**

```python
568 50
```

## Прототип 2. Коробки для упаковки по принципу матрёшки

**Текст задания**

В магазине для упаковки подарков есть `N` кубических коробок. Одну коробку можно поместить в другую, если длина её стороны хотя бы на `3` единицы меньше длины стороны другой коробки. Нужно определить:
- наибольшее количество коробок, которое можно использовать для упаковки одного подарка;
- максимально возможную длину стороны самой маленькой коробки в таком наборе.

Размер подарка позволяет поместить его в самую маленькую коробку.

**Идея решения**

Здесь тоже два вопроса.

Первый вопрос: как получить максимальную длину цепочки коробок.

Второй вопрос: как среди всех таких цепочек сделать самую маленькую коробку как можно больше.

Для первого вопроса жадный подход работает так: после выбора очередной коробки нужно брать ближайшую подходящую коробку, то есть следующую коробку с минимально допустимой разницей, если идём снизу вверх, или с максимально возможным размером, если идём сверху вниз.

Но в этой задаче важен второй вопрос. Нужно не просто набрать максимум коробок, а сделать последнюю, самую маленькую коробку, как можно больше. Поэтому выгодно строить цепочку от самых больших коробок к меньшим и каждый раз выбирать самую большую из подходящих.

Тогда:
- количество коробок остаётся максимальным;
- последняя коробка в цепочке автоматически становится максимально возможной среди всех самых маленьких коробок.

**Первая оптимизация**

Сначала все размеры нужно отсортировать по убыванию.

После этого выбирается самая большая коробка, а затем каждый раз — самая большая из оставшихся коробок, которая хотя бы на `3` единицы меньше предыдущей.

Разберём пример:

```python
15, 16, 18, 19, 20, 21, 25, 27, 30, 32
```

Если идти сверху вниз, получаем такую цепочку:

```python
32, 27, 21, 18, 15
```

Проверим разности:

```python
32 - 27 = 5
27 - 21 = 6
21 - 18 = 3
18 - 15 = 3
```

Все переходы допустимы, значит можно использовать 5 коробок.

Почему выгодно брать именно самую большую подходящую коробку, например после `32` брать `27`, а не `25` или `21`?

Если после `32` взять `21`, то дальше останутся только коробки меньше `18`.

Если после `32` взять `27`, то доступными останутся и `21`, и `18`, и `15`. То есть вариантов продолжения не меньше, а больше. Поэтому локально выгодно брать максимальную подходящую коробку.

**Вторая оптимизация**

Здесь не нужно отдельно перестраивать ответ на второй вопрос, как в задаче с архивом.

Если цепочка сразу строится от больших коробок к меньшим, причём на каждом шаге выбирается максимально возможная подходящая коробка, то последняя коробка цепочки и будет ответом на второй вопрос.

Разберём это на типовом примере из условия:

```python
43, 40, 32, 40, 30
```

После сортировки по убыванию:

```python
43, 40, 40, 32, 30
```

Строим цепочку:

```python
43 -> 40
```

Разница равна `3`, значит переход подходит.

Следующая коробка должна быть не больше `37`. Среди оставшихся подходит `32`, а `30` тоже подходит, но `32` больше. Значит, нужно брать именно `32`.

Получаем:

```python
43 -> 40 -> 32
```

Количество коробок равно `3`, а самая маленькая коробка имеет размер `32`.

Если бы после `40` взяли `30`, цепочка по количеству тоже осталась бы длины `3`, но вторая часть ответа была бы хуже, потому что самая маленькая коробка стала бы меньше.

Именно поэтому в этой задаче направление прохода сразу определяет и второй ответ.

**Код решения**

```python
f = open('26.txt')
n = int(f.readline())
data = sorted((int(x) for x in f), reverse=True)

boxes = [data[0]]

for x in data[1:]:
    if boxes[-1] - x >= 3:
        boxes.append(x)

print(len(boxes), boxes[-1])
```

**Подробный разбор**

Сначала считывается количество коробок:

```python
n = int(f.readline())
```

Переменная `n` показывает, сколько размеров записано во входном файле.

Дальше все размеры считываются в список и сортируются по убыванию:

```python
data = sorted((int(x) for x in f), reverse=True)
```

Теперь в начале списка стоят самые большие коробки.

Список `boxes` хранит коробки, которые уже выбраны в цепочку:

```python
boxes = [data[0]]
```

Сразу кладём в него самую большую коробку. Это удобно, потому что дальше всегда можно сравнивать очередную коробку с последней уже выбранной.

Основной цикл:

```python
for x in data[1:]:
    if boxes[-1] - x >= 3:
        boxes.append(x)
```

Что здесь происходит:
- `x` — очередная коробка из отсортированного списка;
- `boxes[-1]` — последняя выбранная коробка;
- проверяется, можно ли вложить текущую коробку в последнюю выбранную;
- если можно, коробка добавляется в цепочку.

Условие

```python
boxes[-1] - x >= 3
```

означает, что текущая коробка хотя бы на 3 единицы меньше предыдущей.

Разберём короткий пример:

```python
20, 19, 17, 14, 12, 11, 8
```

После сортировки список уже такой же. Работа цикла:

```python
берём 20
19 не подходит, разница 1
17 подходит, разница 3
14 подходит, разница 3
12 не подходит, разница 2
11 подходит, разница 3
8 подходит, разница 3
```

Итоговая цепочка:

```python
[20, 17, 14, 11, 8]
```

Количество коробок равно:

```python
len(boxes)
```

Это ответ на первый вопрос.

Ответ на второй вопрос — это последняя коробка в цепочке:

```python
boxes[-1]
```

Почему именно она?

Потому что цепочка строилась сверху вниз, и на каждом шаге бралась самая большая допустимая коробка. Значит, последняя выбранная коробка — это максимально возможная среди всех коробок, которые могли бы оказаться самыми маленькими при той же длине цепочки.

Для файла из задания программа даёт ответ:

```python
2767 51
```

Это значит:
- подарок можно упаковать в `2767` коробок;
- максимально возможная длина стороны самой маленькой коробки равна `51`.

**Ответ**

```python
2767 51
```

## Прототип 3. Заявки на мероприятия в конференц-зале

**Текст задания**

Во входном файле даны заявки на проведение мероприятий. Для каждой заявки указаны время начала и время окончания. Если одно мероприятие начинается раньше, чем заканчивается другое, провести можно только одно из них. Если одно мероприятие начинается ровно в момент окончания другого, провести можно оба.

Нужно определить:
- максимальное количество мероприятий, которое можно провести;
- максимально возможный перерыв между двумя последними мероприятиями при таком максимальном количестве.

**Идея решения**

Это задача на расписание непересекающихся отрезков.

Первый вопрос: как провести как можно больше мероприятий.

Второй вопрос: как среди всех таких расписаний сделать как можно больше перерыв между двумя последними мероприятиями.

Для первого вопроса действует классический жадный алгоритм: нужно брать мероприятия с самым ранним временем окончания. Тогда зал освобождается как можно раньше, и остаётся больше возможностей поставить следующие мероприятия.

Для этого прототипа удобно использовать полуручное решение.

Сначала кодом находится одно оптимальное расписание и его длина. После этого по найденному списку определяется время окончания предпоследнего мероприятия. Дальше уже по отсортированным заявкам вручную ищется самое позднее мероприятие, которое можно поставить последним.

**Первая оптимизация**

Все мероприятия нужно отсортировать по времени окончания.

После этого выполняется обычный жадный проход: если очередное мероприятие начинается не раньше времени окончания последнего выбранного, его можно брать.

Разберём пример:

```python
(10, 20), (15, 25), (20, 30), (30, 40)
```

После сортировки по окончаниям порядок уже такой же.

Жадный выбор идёт так:

```python
берём (10, 20)
(15, 25) не подходит, потому что 15 < 20
берём (20, 30)
берём (30, 40)
```

Получается 3 мероприятия.

Почему выгодно брать `(10, 20)`, а не `(15, 25)`?

Потому что после окончания в `20` остаётся больше возможных продолжений, чем после окончания в `25`. Более раннее окончание не уменьшает число допустимых следующих мероприятий.

**Вторая оптимизация**

Теперь нужно получить второй ответ, то есть максимальный перерыв между двумя последними мероприятиями.

В полуручном решении здесь используется уже найденное оптимальное расписание.

Логика такая:
- смотрим на предпоследнее мероприятие в найденной цепочке;
- запоминаем время его окончания;
- среди всех заявок ищем те, которые могут начаться не раньше этого момента;
- выбираем из них самое позднее по времени начала.

Тогда количество мероприятий не изменится, а перерыв перед последним мероприятием станет максимально возможным.

Разберём пример из условия:

```python
(10, 150), (100, 120), (131, 170), (150, 180), (120, 130)
```

Максимум по количеству равен `3`.

Можно взять:

```python
(100, 120), (120, 130), (131, 170)
```

Тогда перерыв между двумя последними мероприятиями равен:

```python
131 - 130 = 1
```

Но можно взять другой вариант:

```python
(100, 120), (120, 130), (150, 180)
```

Теперь перерыв между двумя последними мероприятиями равен:

```python
150 - 130 = 20
```

Количество мероприятий осталось тем же, но второй ответ стал лучше.

Именно поэтому после нахождения максимума по количеству нужно отдельно работать с последними двумя мероприятиями.

**Код решения**

```python
f = open('26.txt')
n = int(f.readline())
data = []

for s in f:
    start, end = [int(x) for x in s.split()]
    data.append([start, end])

data.sort(key=lambda x: x[1])

last = -1
a = []

for conf in data:
    if conf[0] >= last:
        last = conf[1]
        a.append(conf)

# 1273 — время окончания предпоследнего мероприятия
# print(a)
data.sort(reverse=True)
print(len(a))
# print(data)
```

**Подробный разбор**

Сначала считываются все заявки:

```python
n = int(f.readline())
data = []
```

Дальше каждая строка файла разбирается на время начала и окончания:

```python
for s in f:
    start, end = [int(x) for x in s.split()]
    data.append([start, end])
```

После этого в `data` лежат пары вида:

```python
[время_начала, время_окончания]
```

Дальше список сортируется по времени окончания:

```python
data.sort(key=lambda x: x[1])
```

Это основа жадного алгоритма для первого вопроса.

Первый проход:

```python
last = -1
a = []

for conf in data:
    if conf[0] >= last:
        last = conf[1]
        a.append(conf)
```

Здесь:
- `last` — время окончания последнего выбранного мероприятия;
- `conf[0]` — время начала текущей заявки;
- `conf[1]` — время её окончания;
- если начало текущего мероприятия не раньше `last`, заявку можно брать;
- тогда время окончания обновляется, а сама заявка попадает в список `a`.

После этого:

```python
len(a)
```

Это ответ на первый вопрос.

Теперь второй ответ ищется вручную по найденному списку `a`.

После жадного прохода можно вывести `a` и посмотреть, какие мероприятия были выбраны:

```python
# print(a)
```

По этому списку видно время окончания предпоследнего мероприятия. В твоём решении это число:

```python
1273
```

Именно поэтому в коде оставлен комментарий:

```python
# 1273 — время окончания предпоследнего мероприятия
```

Дальше весь список заявок переворачивается:

```python
data.sort(reverse=True)
```

После такой сортировки в начале списка оказываются заявки с большими временами начала. Для ручной добивки ответа это удобно: можно смотреть сверху вниз и искать самое позднее мероприятие, которое начинается не раньше `1273`.

Идея ручного шага такая:
- максимальное количество мероприятий уже найдено, это `len(a)`;
- предпоследнее мероприятие заканчивается в `1273`;
- последнее мероприятие должно начинаться не раньше `1273`;
- чтобы перерыв был максимальным, нужно выбрать заявку с максимально возможным временем начала.

Под этот код ответ получается так.

Сначала программа находит:

```python
len(a) = 32
```

Это первый ответ.

Потом по списку `a` определяется, что предпоследнее мероприятие заканчивается в `1273`.

После этого просматривается перевёрнутый список `data`, и среди заявок, у которых начало не меньше `1273`, выбирается самая поздняя допустимая по началу.

В данном файле такая заявка начинается в:

```python
1288
```

Тогда перерыв между двумя последними мероприятиями равен:

```python
1288 - 1273 = 15
```

Значит, окончательный ответ:

```python
32 15
```

Разберём это ещё на коротком учебном примере.

Пусть после жадного прохода получено оптимальное расписание из 4 мероприятий, и предпоследнее из них заканчивается в `200`.

Среди оставшихся заявок есть такие начала:

```python
205, 210, 240, 250
```

Все они подходят как последние мероприятия, потому что начинаются не раньше `200`.

Но перерывы будут разными:

```python
205 - 200 = 5
210 - 200 = 10
240 - 200 = 40
250 - 200 = 50
```

Значит, для второго ответа нужно брать мероприятие с самым поздним началом, то есть здесь это `250`.

Для файла из задания программа даёт ответ:

```python
32 15
```

Это значит:
- в конференц-зале можно провести максимум `32` мероприятия;
- максимально возможный перерыв между двумя последними мероприятиями равен `15` минутам.

**Ответ**

```python
32 15
```
