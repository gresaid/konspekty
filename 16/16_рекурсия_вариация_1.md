# ТЕОРИЯ

## Что проверяет задание 16

В задании 16 функция задаётся рекуррентными соотношениями. Нужно аккуратно перевести математическое описание в код, правильно записать базовые случаи и понять, каким способом удобнее считать значение функции.

Обычно в условии есть:
- базовое значение функции;
- одно или несколько рекурсивных правил;
- значение функции, выражение или количество аргументов, которые нужно найти.

Базовый рекурсивный шаблон:

```python
def f(n):
    if n == 1:
        return 1
    return n + f(n - 1)


print(f(10))
```

Сначала записывается базовый случай. Он останавливает рекурсию. После него записываются рекурсивные переходы.

## `setrecursionlimit`

В Python есть ограничение на глубину рекурсивных вызовов. Если функция вызывает сама себя слишком много раз подряд, появляется ошибка:

```text
RecursionError: maximum recursion depth exceeded
```

Чтобы разрешить более глубокую рекурсию, используют:

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)
```

Важно: в Python функция называется `setrecursionlimit`, а не `setRecursionLimit`.

Этот способ решает только проблему глубины рекурсии. Он не ускоряет программу, не убирает повторные вычисления и не уменьшает расход памяти.

## `lru_cache`

Кэширование используют, когда одни и те же значения функции могут понадобиться несколько раз:

```python
from functools import lru_cache


@lru_cache(None)
def f(n):
    if n == 1:
        return 1
    return n + f(n - 1)
```

Запись `@lru_cache(None)` означает, что размер кэша не ограничен. То же самое можно записать подробнее:

```python
@lru_cache(maxsize=None)
```

Если значения функции становятся очень большими, безлимитный кэш может занять много памяти. Тогда можно ограничить количество хранимых значений:

```python
@lru_cache(1000)
```

Такой кэш хранит только последние `1000` результатов. Это полезно, если для вычисления следующего значения нужны только недавние значения, например `F(n - 5)`.

Кэш хранит уже найденные значения. Если значение `f(100)` было посчитано раньше, повторный вызов `f(100)` сразу берётся из памяти.

Важно различать две ситуации:
- `lru_cache` убирает повторные вычисления;
- `lru_cache` сам по себе не убирает глубину первого рекурсивного вызова.

Если сразу вызвать `f(2024)`, а функция идёт к `f(2023)`, `f(2022)` и так далее, кэш ещё пустой. Первый проход всё равно будет глубоким. Поэтому в некоторых задачах кэш нужно заранее заполнить в правильном порядке.

Если функция зависит от меньших аргументов, кэш заполняют снизу вверх. Когда `0` попадает в базовый случай, удобно писать простой диапазон от нуля:

```python
for i in range(2025):
    f(i)
```

Если базовый случай начинается с `1`, диапазон начинают с `1`:

```python
for i in range(1, 2025):
    f(i)
```

Если функция зависит от больших аргументов, кэш заполняют с конца:

```python
for i in range(10003, -1, -1):
    f(i)
```

Обычно лучше брать простой диапазон с запасом. Он чуть шире, зато понятнее и меньше провоцирует ошибку в границах.

Так каждый новый вызов опирается на уже закэшированное значение, и глубокой рекурсии не возникает.

## Аналитическое решение

Аналитическое решение — это решение через формулы и сокращения, без вычисления всех значений функции.

Оно особенно полезно, когда:
- выражение содержит разность похожих значений;
- значения функции быстро становятся огромными;
- рекурсивный код требует слишком много памяти;
- можно понять цепочку переходов и записать её короткой формулой.

Пример:

```text
F(2024) - F(2021) = 2024 + 2023 + 2022.
```

В Markdown удобно оформлять такие рассуждения обычным текстовым блоком:

```text
F(2024) - F(2021) = 2024 + 2023 + 2022 = 6069
```

## Типичные ошибки

- Использовать `lru_cache` и думать, что он автоматически решает проблему глубины рекурсии.
- Добавлять `setrecursionlimit` везде без анализа.
- Не заполнять кэш там, где первый вызов остаётся слишком глубоким.
- Писать `/` вместо `//`, когда аргумент функции должен быть целым.
- Считать огромные значения функции, хотя в выражении они сокращаются.

## Прототип 1. Короткая рекурсия с чётностью

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — натуральное число, задан следующими соотношениями:

```text
F(n) = 1 при n = 1;
F(n) = n + F(n - 1), если n чётно;
F(n) = 2 * F(n - 2), если n > 1 и при этом n нечётно.
```

Чему равно значение функции `F(26)`?

**Идея решения**

Аргумент маленький, цепочка вызовов короткая. Здесь не нужны ни увеличение лимита, ни кэширование. Достаточно прямой рекурсии.

**Код решения**

```python
def f(n):
    if n == 1:
        return 1
    if n % 2 == 0:
        return n + f(n - 1)
    return 2 * f(n - 2)


print(f(26))
```

**Разбор решения**

Базовый случай `n = 1` останавливает рекурсию. Для чётного `n` используется переход к `n - 1`, для нечётного `n > 1` — переход к `n - 2`.

`lru_cache` здесь не нужен: повторных тяжёлых вычислений нет, а глубина рекурсии мала.

**Аналитическое решение**

Можно последовательно раскрывать значения:

```text
F(1) = 1
F(2) = 2 + F(1) = 3
F(3) = 2 * F(1) = 2
```

и так далее до `F(26)`. Такой способ возможен, но для `26` он длинный и хуже прямого кода.

**Ответ**

```text
4122
```

## Прототип 2. Длинная цепочка вниз

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — натуральное число, задан следующими соотношениями:

```text
F(n) = n при n < 11;
F(n) = n + F(n - 1), если n >= 11.
```

Чему равно значение выражения `F(2024) - F(2021)`?

**Идея решения**

Прямой вызов `F(2024)` создаёт длинную цепочку к `F(10)`. Здесь можно использовать `setrecursionlimit`, либо заполнить кэш снизу вверх, либо решить выражение аналитически.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n < 11:
        return n
    return n + f(n - 1)


print(f(2024) - f(2021))
```

Увеличение лимита нужно, потому что первый вызов идёт глубокой цепочкой вниз.

**Вариант 2. Через `lru_cache` с заполнением**

```python
from functools import lru_cache


@lru_cache(None)
def f(n):
    if n < 11:
        return n
    return n + f(n - 1)


for i in range(2025):
    f(i)

print(f(2024) - f(2021))
```

Здесь `setrecursionlimit` не нужен: кэш заполняется снизу вверх. Когда вызывается `f(100)`, значение `f(99)` уже лежит в кэше, поэтому глубокая цепочка не строится. Вызов `f(0)` безопасен, потому что по условию при `n < 11` функция сразу возвращает `n`.

**Аналитическое решение**

Для `n >= 11` функция накапливает сумму:

```text
F(n) = n + (n - 1) + (n - 2) + ... + 11 + F(10)
```

При вычитании общая часть сокращается:

```text
F(2024) - F(2021) = 2024 + 2023 + 2022 = 6069
```

**Ответ**

```text
6069
```

## Прототип 3. Рекурсия вверх

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — натуральное число, задан следующими соотношениями:

```text
F(n) = 1, если n > 10000;
F(n) = F(n + 3) + 7, если n < 10000 и чётное;
F(n) = F(n + 1) - 3, если n < 10000 и нечётное.
```

Чему равно значение выражения `F(50) - F(57)`?

**Идея решения**

Аргумент увеличивается до области `n > 10000`. Если вызвать `F(50)` сразу, получится длинная рекурсия вверх. Кэш нужно заполнять с конца, потому что каждое значение зависит от большего аргумента.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n > 10000:
        return 1
    if n % 2 == 0:
        return f(n + 3) + 7
    return f(n + 1) - 3


print(f(50) - f(57))
```

Этот вариант работает за счёт увеличения допустимой глубины рекурсии.

**Вариант 2. Через `lru_cache` с заполнением с конца**

```python
from functools import lru_cache


@lru_cache(None)
def f(n):
    if n > 10000:
        return 1
    if n % 2 == 0:
        return f(n + 3) + 7
    return f(n + 1) - 3


for i in range(10003, -1, -1):
    f(i)

print(f(50) - f(57))
```

Ключевой момент: кэш заполняется справа налево. Диапазон берётся с запасом до `0`, чтобы не высчитывать нижнюю границу вручную. Сначала вызываются значения за базовой границей, потом значения около `10000`, потом меньшие. Поэтому при вычислении `f(i)` нужные `f(i + 1)` или `f(i + 3)` уже есть в кэше.

Если просто написать `@lru_cache(None)` и сразу вызвать `f(50)`, первый проход всё равно будет глубоким. В таком виде задачу решал бы не кэш, а только `setrecursionlimit`.

**Аналитическое решение**

Для чётного `n`:

```text
F(n) = F(n + 3) + 7
```

Так как `n+3` нечётно, следующий шаг:

```text
F(n + 3) = F(n + 4) - 3
```

Значит за два шага от чётного `n` к чётному `n+4` добавляется:

```text
F(n) = F(n + 4) + 4
```

Дальше можно рассматривать цепочку с шагом `4` до границы `10000`. Аналитически это возможно, но громоздко; для этой задачи практичнее код с заполнением кэша.

**Ответ**

```text
11
```

## Прототип 4. Факториальный рост

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — натуральное число, задан следующими соотношениями:

```text
F(n) = 1 при n = 1;
F(n) = n * F(n - 1), если n > 1.
```

Чему равно значение выражения `(2 * F(2024) + F(2023)) / F(2022)`?

**Идея решения**

Функция задаёт факториал. Прямой код возможен, но лучше сократить выражение.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n == 1:
        return 1
    return n * f(n - 1)


print((2 * f(2024) + f(2023)) // f(2022))
```

Код напрямую повторяет условие, но считает огромные числа.

**Вариант 2. Через `lru_cache` с заполнением**

```python
from functools import lru_cache


@lru_cache(None)
def f(n):
    if n == 1:
        return 1
    return n * f(n - 1)


for i in range(1, 2025):
    f(i)

print((2 * f(2024) + f(2023)) // f(2022))
```

Кэш заполняется снизу вверх, поэтому `setrecursionlimit` не нужен. Здесь нельзя начинать с `0`, потому что базовый случай задан как `n = 1`. Кэш всё равно хранит большие числа, поэтому аналитическое сокращение надёжнее.

**Аналитическое решение**

По рекуррентной формуле:

```text
F(2023) = 2023 * F(2022)
F(2024) = 2024 * 2023 * F(2022)
```

Тогда:

```text
(2 * F(2024) + F(2023)) / F(2022)
= (2 * 2024 * 2023 * F(2022) + 2023 * F(2022)) / F(2022)
```

Сокращаем `F(2022)`:

```text
2 * 2024 * 2023 + 2023 = 8191127
```

**Ответ**

```text
8191127
```

## Прототип 5. Количество значений на отрезке

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — целое число, задан следующими соотношениями:

```text
F(n) = n при n < 2;
F(n) = F(n / 2) + 1, когда n >= 2 и чётное;
F(n) = F(3 * n + 1) + 1, когда n >= 2 и нечётное.
```

Назовите количество значений `n` на отрезке `[1; 100000]`, для которых `F(n)` равно `16`.

**Идея решения**

Нужно перебрать все значения `n` на отрезке. Здесь кэширование полезно, потому что разные стартовые числа могут попадать в одни и те же промежуточные значения.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n < 2:
        return n
    if n % 2 == 0:
        return f(n // 2) + 1
    return f(3 * n + 1) + 1


cnt = 0

for n in range(1, 100001):
    if f(n) == 16:
        cnt += 1

print(cnt)
```

Этот вариант решает задачу прямым перебором, но повторяет много вычислений.

**Вариант 2. Через `lru_cache`**

```python
from functools import lru_cache
from sys import setrecursionlimit

setrecursionlimit(10**6)


@lru_cache(None)
def f(n):
    if n < 2:
        return n
    if n % 2 == 0:
        return f(n // 2) + 1
    return f(3 * n + 1) + 1


cnt = 0

for n in range(1, 100001):
    if f(n) == 16:
        cnt += 1

print(cnt)
```

В этой задаче заранее заполнить кэш простым порядком трудно: для нечётного `n` переход идёт к `3n+1`, то есть аргумент может сначала сильно увеличиваться. Поэтому кэш наполняется по мере перебора.

`setrecursionlimit` оставлен не из-за кэша, а как защита от длинной цепочки для отдельных значений. Кэш отвечает за уменьшение повторных вычислений.

**Аналитическое решение**

Полностью аналитический подсчёт для всех `n` на отрезке `[1;100000]` неудобен: траектория зависит от чётности каждого промежуточного значения и может сначала расти, а потом уменьшаться.

Здесь естественный способ — программный перебор с кэшированием.

**Ответ**

```text
24
```

## Прототип 6. Минимальное значение аргумента

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — целое число, задан следующими соотношениями:

```text
F(1) = 1;
F(n) = F(n / 2) + 1, когда n >= 2 и чётное;
F(n) = F(n - 1) + 1, когда n > 2 и нечётное.
```

Назовите минимальное значение `n`, для которого `F(n)` равно `19`.

**Идея решения**

Можно перебирать `n` по возрастанию. Так как каждое `F(n)` зависит от меньшего аргумента, кэш заполняется естественно.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n == 1:
        return 1
    if n % 2 == 0:
        return f(n // 2) + 1
    return f(n - 1) + 1


n = 1

while f(n) != 19:
    n += 1

print(n)
```

Здесь увеличение лимита не является принципиальным, потому что глубина цепочки небольшая. Но шаблон безопасен для похожих задач.

**Вариант 2. Через `lru_cache`**

```python
from functools import lru_cache


@lru_cache(None)
def f(n):
    if n == 1:
        return 1
    if n % 2 == 0:
        return f(n // 2) + 1
    return f(n - 1) + 1


n = 1

while f(n) != 19:
    n += 1

print(n)
```

Отдельный цикл заполнения кэша не нужен: перебор идёт по возрастанию, а функция обращается только к меньшим аргументам. К моменту проверки нового `n` нужные меньшие значения уже обычно посчитаны.

**Аналитическое решение**

Функция считает количество шагов до `1`:
- чётное число делится на `2`;
- нечётное число уменьшается на `1`.

Чтобы получить минимальное `n` при заданном количестве шагов, выгодно как можно дольше идти по числам вида:

```text
1, 2, 3, 6, 7, 14, 15, ...
```

Для таких чисел:

```text
n = 2^k - 1
```

Проверим значение:

```text
2^10 - 1 = 1023
```

Цепочка:

```text
1023 -> 1022 -> 511 -> 510 -> 255 -> 254 -> 127 -> 126 -> 63 -> 62 -> 31 -> 30 -> 15 -> 14 -> 7 -> 6 -> 3 -> 2 -> 1
```

В этой цепочке `18` переходов, а так как `F(1)=1`, получаем:

```text
F(1023) = 19
```

**Ответ**

```text
1023
```

## Прототип 7. Две взаимосвязанные функции

**Текст задания**

Алгоритм вычисления функций `F(n)` и `G(n)`, где `n` — целое число, задан следующими соотношениями:

```text
F(n) = F(n - 8) + 1095, если n >= 21;
F(n) = 10 * (G(n - 7) - 36), если n < 21;
G(n) = n / 23 + 33, если n >= 22560;
G(n) = G(n + 11) - 4, если n < 22560.
```

Чему равно значение функции `F(548)`?

**Идея решения**

`F` идёт вниз с шагом `8`, а затем вызывает `G`. Функция `G` идёт вверх с шагом `11`. Здесь можно решить напрямую с лимитом, кэшем с правильным заполнением или аналитически.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def g(n):
    if n >= 22560:
        return n / 23 + 33
    return g(n + 11) - 4


def f(n):
    if n >= 21:
        return f(n - 8) + 1095
    return 10 * (g(n - 7) - 36)


print(int(f(548)))
```

Лимит нужен из-за длинной цепочки в функции `G`.

**Вариант 2. Через `lru_cache` с заполнением нужных цепочек**

```python
from functools import lru_cache


@lru_cache(None)
def g(n):
    if n >= 22560:
        return n / 23 + 33
    return g(n + 11) - 4


@lru_cache(None)
def f(n):
    if n >= 21:
        return f(n - 8) + 1095
    return 10 * (g(n - 7) - 36)


for x in range(22560, -8, -1):
    g(x)

for x in range(549):
    f(x)

print(int(f(548)))
```

Кэш заполняется простыми диапазонами с запасом:
- для `G` идём справа налево от `22560` до отрицательных значений, потому что `F(20)` вызывает `G(13)`, а при заполнении `F` с нуля появятся и меньшие аргументы `G`;
- для `F` идём от `0` до `548`, потому что `F(n)` при `n >= 21` зависит от меньшего аргумента `F(n - 8)`.

Такой вариант проще читать: не нужно отдельно высчитывать нужный остаток по модулю `8` или `11`.

**Аналитическое решение**

Сначала считаем, сколько раз функция `F` уменьшает аргумент:

```text
548 - 8 * 66 = 20
```

Значит:

```text
F(548) = F(20) + 66 * 1095
```

Так как `20 < 21`,

```text
F(20) = 10 * (G(13) - 36)
```

Для `G(13)` нужно дойти до первого числа не меньше `22560` с шагом `11`:

```text
13 + 11 * k >= 22560
```

Минимальное такое `k`:

```text
k = округление вверх((22560 - 13) / 11) = 2050
```

Тогда:

```text
13 + 11 * 2050 = 22563
```

Значит:

```text
G(13) = 22563 / 23 + 33 - 4 * 2050
```

После подстановки:

```text
F(548) = 66 * 1095 + 10 * (G(13) - 36) = 50
```

**Ответ**

```text
50
```

## Прототип 8. Большой аргумент и сокращение выражения

**Текст задания**

Алгоритм вычисления значения функции `F(n)`, где `n` — целое число, задан следующими соотношениями:

```text
F(n) = 3 при n < 10;
F(n) = (n + 4) * F(n - 5), если n >= 10.
```

Чему равно значение выражения `(F(257487) / 683 + 67 * F(257477)) / F(257472)`?

В ответе запишите целую часть полученного числа.

**Идея решения**

Эта задача показывает ограничение прямой рекурсии и кэша. Значения функции становятся огромными, поэтому на слабом компьютере рекурсивное решение может съесть слишком много памяти. Надёжный путь — аналитическое сокращение.

**Вариант 1. Через `setrecursionlimit`**

```python
from sys import setrecursionlimit

setrecursionlimit(10**6)


def f(n):
    if n < 10:
        return 3
    return (n + 4) * f(n - 5)


print((f(257487) + 683 * 67 * f(257477)) // (683 * f(257472)))
```

Этот код записывает условие напрямую, но практически плох: он создаёт огромные промежуточные значения.

**Вариант 2. Через `lru_cache`**

```python
from functools import lru_cache


@lru_cache(1000)
def f(n):
    if n < 10:
        return 3
    return (n + 4) * f(n - 5)


for i in range(257488):
    f(i)

print(int((f(257487) / 683 + 67 * f(257477)) / f(257472)))
```

Кэш заполняется снизу вверх обычным диапазоном `range(257488)`. Здесь важно не использовать безлимитный `@lru_cache(None)`: значения функции огромные, и если хранить их все, память быстро закончится.

Ограничение `@lru_cache(1000)` хранит только последние `1000` значений. Этого достаточно, потому что каждое новое значение зависит от `F(n - 5)`, то есть от недавнего результата. Поэтому переполнения памяти не происходит.

В выводе используется не обычное деление `/`, а точная целочисленная форма. Вместо выражения

```text
(F(257487) / 683 + 67 * F(257477)) / F(257472)
```

пишем равносильное выражение:

```text
(F(257487) + 683 * 67 * F(257477)) // (683 * F(257472))
```

Так Python работает с целыми числами и не пытается преобразовать гигантское значение во `float`.

**Аналитическое решение**

Обозначим:

```text
n = 257472
```

Тогда:

```text
257477 = n + 5
257487 = n + 15
```

По рекуррентной формуле:

```text
F(n + 5) = (n + 9) * F(n)
F(n + 10) = (n + 14) * (n + 9) * F(n)
F(n + 15) = (n + 19) * (n + 14) * (n + 9) * F(n)
```

Подставим в выражение:

```text
(F(n + 15) / 683 + 67 * F(n + 5)) / F(n)
= ((n + 19) * (n + 14) * (n + 9)) / 683 + 67 * (n + 9)
```

Нужна целая часть:

```text
целая часть от (((n + 19) * (n + 14) * (n + 9)) / 683 + 67 * (n + 9))
```

При `n = 257472`:

```text
целая часть от (257491 * 257486 * 257481 / 683 + 67 * 257481)
= 24994270044009
```

**Ответ**

```text
24994270044009
```
